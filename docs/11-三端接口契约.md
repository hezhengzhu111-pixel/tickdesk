# 11 · 三端接口契约 v2

契约版本 **2.0.0**，修订日期2026-11-15。是待实现设计，不表示三端已经完成。云端仅中继，本地业务事实源，App缓存和待发；原图本地保留可手动删除。

## 1. 权威文件

[business.schema.json](../contracts/v2/business.schema.json)定义命令、结果、事件和恢复证据。[commands.json](../contracts/v2/commands.json)定义读写及恢复许可，[relay.schema.json](../contracts/v2/relay.schema.json)定义传输，[cloud.openapi.json](../contracts/v2/cloud.openapi.json)定义 WS 升级及健康检查。字段以 schema 为准。[样例与校验](../contracts/README.md)

v1云账号、好友、文件、历史API和2000字符分片已废弃。v1不能连v2；旧部署迁移先导出业务/文件与审计、停止旧写入、离线校验后导入并创建新epoch/incarnation；App重新配对同步。旧主版本证据保留人工核对，不转换成新写命令。无现有生产数据时直接初始化v2。

## 2. 传输规范

`wss://IP:8443/relay/v2/connect`，Authorization Bearer，Sec-WebSocket-Protocol: tickdesk.v2。令牌随机32bytes→无padding base64url；摘要SHA256(ASCII(token))。QR仅app角色令牌/pairId/url/pins/protocol。welcome回显pairId/角色/会话；角色由令牌推导，云不信任客户端目标。

hello/welcome/presence为连接控制，deliver包含deliveryId/fromIncarnation/toIncarnation/category/payloadHash/payload；payloadHash为完整payload的TD-C14N-1 SHA256。category=business时payload为完整业务信封，file_chunk时为32KiB以内块及hash。WS完整消息≤128KiB，业务payload≤64KiB，不再业务分片。超过大小在业务提交前拒绝或分页。

receipt原样回显deliver的deliveryId/hash/from/to，不反转字段；只在对端持久化后发。云核对receipt发送连接==to、接收连接==from；deliver反之。业务ack另经deliver投递。发送返回/receipt/ack含义不同。错误frame不使原消息成功，retryable及refDeliveryId决定退避或隔离；消息丢失时仍由端点超时重试。

方向：App只发command/file_chunk及receipt/error，local发ack/业务事件/file_chunk及receipt/error；hello只端点→云，welcome/presence只云→端点。本地拒绝从App来的ack/task等伪服务事件，App拒绝来自非local的业务结果。receipt/hash/schema校验前不能推进接收状态。

心跳15/45秒、重连、会话fence、队列边界、并发文件原子性、恢复机制详见 [云端设计](design/cloud-service.md)，属于本契约的规范性部分。

## 3. 文件、历史与旧命令查询

accept_vision_notice(noticeVersion,accepted) 明确同意或撤销。accepted=false将consentedAt置null并取消尚未发往外部的识别任务，禁止新外发；已发出的请求无法撤回第三方数据，取消其结果应用。重新同意使用新clientMsgId。

- begin_upload(name,mime,sizeBytes,sha256)→Upload。PNG/JPEG≤20MiB、≤40MP，chunkSize=32768，总块数ceil(size/32768)。单块index/total/hash与持久manifest一致，尾块长度精确。
- get_upload(uploadId)→Upload及已落盘receivedChunks，重连补传；接收块超过范围/状态不对拒绝。临时上传24h无活动过期，已完成文件不受此TTL影响。只有cancel_transfer成功或新get_upload明确expired/cancelled后，相关块可进入终态停止重发；单纯超时不能当取消成功。
- finalize_upload(uploadId)→File.available，只在完整hash/实际类型/文件刷新rename+metadata提交后成功；不自动识别。重复完成同ID返回原fileId，不复制原图。
- register_image(importId,fileId,autoApply?)→pending，需当前 vision-v2 视觉告知同意且file available；autoApply缺省false保持草稿预览确认，true表示选图后校验并直接更新图中持仓，缺失持仓保留。同file可用新importId重新识别，但每importId绑定同一file及autoApply意图。Import始终带fileId/fileStatus。识别与120秒deadline持久化，迟到结果不得覆盖终态。
- cancel_import(importId)→cancelled/already_terminal，取消不撤销已确认持仓。cancel_transfer(transferId,kind)→cancelled/already_complete；持久取消墓碑拒绝迟到块。下载全部块receipt、取消或24h到期均释放lease。
- list_files(cursor?,limit?)→File[]+nextCursor，默认20最多20，固定10分钟读取快照，createdAt降序/fileId升序；可包含删除墓碑。read_file(fileId)→downloadId+File+块数/expiry，local发file_chunk，App核验总hash后查看；下载中断同incarnation重发未receipt块，状态丢失可新建read_file。
- delete_file(fileId,baseVersion,confirm=true)→File.deleted；lease和版本CAS，先deleting再清bytes/缩略图并提交墓碑。FILE_BUSY等已确定拒绝沿原键仍返回拒绝，解除占用后的新操作使用新clientMsgId；未知提交结果沿原键查询/重试。
- get_messages(cursor?,limit?)→本地持久对话Message[]+nextCursor；默认20最多20，at降序/messageId升序，10分钟快照游标绑定查询。单页同时满足64KiB。空集合nextCursor=null；游标篡改INVALID_PARAMS、过期SNAPSHOT_EXPIRED。聊天user项在chat接受事务保存，assistant项在最终reply事务保存，requestId关联同一意图。Message按role区分：user保留原text（上限8000），assistant完整保留出站Reply。发布同时预检事件与历史封装，超过64KiB或出站正文上限时使用节选，`sources[0].ref` 用 `local:chat-output:` 前缀标记。支持新命令的App可用requestId分页读取通过核验的完整正文。历史附件引用记录当时ID/scanId，不把当前数据伪装成当时快照。
- `list_reports(symbol?,cursor?,limit?,subscribe?)` 分页读取当前配对、纪元和 fence 的原始综合报告。默认及最大页长为 20，根据证据截止时点和报告 ID 降序翻页。续页带回同一证券过滤条件。`ReportHeader` 展示生成时间、证据截止时间、有效期、最新或历史状态、结论及覆盖。
- `get_report(reportId)` 读取已保存的报告正文与来源，超出单帧时使用同一节选标记。报告 ID 可用于追问或读取完整正文。报告不可读取时返回 `AI_REPORT_UNAVAILABLE`。查看列表和详情无需调用模型。
- `get_reply_page(requestId,offset?,sha256?)` 读取原配对、当前纪元和 fence 下成功完成的完整正文。报告使用 `header.reportId`。首请求可省 offset 与 sha256；后续页用 `nextOffset` 和首个 `sha256`。响应包含 `requestId`、`offset`、`nextOffset`、`totalChars`、`sha256`、`text` 和 `sources`。位置和总长按 Unicode 码点计数，每页至多 2048 码点，末页 `nextOffset=null`。完整 UTF-8 正文的 SHA-256 在所有页相同，拼接后核验。原始核验来源只随第一页返回。命令不调用模型。页码或摘要不匹配返回 `INVALID_PARAMS`，待完成、失败或无权限的回复统一返回 `AI_REPLY_UNAVAILABLE`，恢复门禁期间不可读。命令及状态查询的历史回执在当前访问边界内可重放。
- App 支持 `analysis_report` 时，可在首屏的 `list_reports` 请求附 `subscribe=true`。订阅绑定当前配对、纪元和 fence。定时报告仍有效且符合发布条件时，报告头与 `analysis_report` outbox 在同一事务提交。`notifyUntil` 为可提示的截止时间或 `null`。有截止时间的事件仍需在展示前核验纪元、对象状态、到期时间、用户通知设置和去重。
- get_command_status(originalEpoch,targetClientMsgId,targetRequestHash)→found/processing/quarantined/not_found/hash_mismatch及ackEventId。found必有ackEventId并向当前App重投完整原ack，其他为null；同时查账本与inbox；每次刷新查询使用新查询clientMsgId，目标三元组不变，避免重放旧processing结果。not_found不是未执行证明，恢复后的未知意图不可自动执行。原epoch ack只作证据，不更新新epoch状态。

文件/历史不加入七集合业务sync：相关写成功后及回前台独立刷新list_files/get_messages。删除原图成功时推进业务快照序号，下一次 `sync` 返回关联批次的新文件状态，保留识别及入账结果。Import.fileStatus是该事件/快照当时状态，查看原图前以最新File为准。文件跨命令失败统一见errors.json；未知错误也视为失败，不能默认成功。

## 4. 业务信封、类型和规范化

- `v=2` 是协议主版本；契约包版本是 2.0.0。命令信封字段固定 `v,kind,id,dedupeKey,ts,serverEpoch,data`；服务端事件另必带顶层 snapshotSeq。所有 ID 均非空 ASCII；逻辑 eventId（id）最多61字符，业务 ID 最多64字符。
- `id` 是逻辑事件 ID；`data.clientMsgId` 是命令幂等 ID，允许且样例特意令二者不同；`ack.data.refId` 指首次命令 id，ack.data.clientMsgId 指幂等 ID。不得混用它们与 IM messageId。
- 时间统一 unix 毫秒，业务时区 Asia/Shanghai；交易日用 YYYY-MM-DD。JSON 整数限制 ±(2^53−1)，数量/版本非负，真实成交数量为正整数。所有价格、金额、比例和评分均用十进制字符串；比例 `0.1` 表示10%，不含百分号。未知字段值按 schema 用 null，空数组表示已知无记录；不能用0冒充未知。
- 金额不使用二进制浮点；成交价格>0，已确认持仓成本非空且≥0；识别阶段缺成本须保留待修正。显示可四舍五入，传输和存储不按显示精度裁剪。score 在0–100内。所有文本须为有效 Unicode 标量，不允许未配对 surrogate。
- `TD-C14N-1`：对象键限 ASCII 并递归升序，数组顺序保留；UTF-8、无 BOM/空格；整数十进制无前导0、无指数、无小数点，禁止负零；字符串不转义非 ASCII 或 `/`，仅转义 `"`、`\` 及控制字符（使用 JSON 标准短转义，其他控制字符小写 `\u00xx`）；不做 Unicode 归一化。参考实现和向量在契约包。
- 在解析原始JSON时拒绝重复键、非整数数值及负零，不能等解析器覆盖/转换后再计算hash。此规则同样适用于v2传输JSON。
- requestHash 对完整原始 data 规范化后算 SHA-256 小写hex；不含外层 ts、deliveryId。ack.data.requestHash 必填，App以clientMsgId+requestHash关联原意图，不能把另一载荷的拒绝回执覆盖首次成功。不能先注入默认值、删可选字段、把null当缺省或格式化十进制再算 hash；`"10.0"` 与 `"10.00"` 作为不同请求字面量。未知写命令字段拒绝，避免拼写错误被默默丢弃。
- 同一 clientMsgId+同 hash 永久返回首次完整 ack；不同 hash 返回 COMMAND_ID_REUSED。先核对身份与 epoch，再查当前纪元幂等。首次业务拒绝也持久化；网络不确定沿用原 ID，用户改意图才生成新 ID。
- 正常ack去重键为`ack:{clientMsgId}`；COMMAND_ID_REUSED与SERVER_EPOCH_MISMATCH这类不属于首次命令结果的拒绝使用`ack_reject:{currentEpoch}:{clientMsgId}:{requestHash}`，独立保存、不覆盖首次ack。App业务去重键总是以当前epoch为命名空间；恢复前旧outbox保持隔离。
- 服务端异步事件可乱序、重复，ack 也可能晚于 task_update。按 eventId/dedupeKey 去重，按对象 version/revision 更新状态；同一 snapshotSeq 可以有多个不同事件，不能仅凭“序号不大于最大值”丢弃 ack 或另一对象的事件。


## 5. 命令与成功回执

完整字段从 `cmd_<名称>` / `result_<名称>` 取，不能用一个无约束的任意 JSON result 替代。成功 ack 的 ok=true、error=null；失败 ok=false、error必填，result通常null，仅扫描失败/部分结果允许返回 Scan。`record_execution/act` 的真实成交字段集中在 result.execution，持仓在 result.position；可用不足时 execution 存在但 positionEffect=needs_reconciliation，不能看 ok=true 就当已扣减持仓。

| 组 | 命令 | 开发责任 |
|---|---|---|
| 事项 | act、ignore、snooze、get_task、get_task_actions | 本地做状态/操作版本校验，App 展示完整task及分页操作记录；risk无成交act不生成execution |
| 持仓 | record_execution、adjust_position | 本地事务与对账，App 独立补录/更正入口；不依赖有效事项 |
| 量化持仓与进度 | get_holding_details、reconcile_holding、get_execution_progress、set_execution_progress | 本地维护分区及执行意图，App 通过能力探针核验支持后使用 |
| 控制与关注 | set_profile、set_settings、pause、resume、scan_now、watch、unwatch | 本地持久化并给权威回执，App 失败/离线不显示生效 |
| 读取 | sync、get_status、get_candidates、search_symbols、get_chart、get_quote_status、get_history_coverage、get_logs | 本地提供可渲染 DTO，App 无需解析内核原始返回 |
| 对话与图片 | chat、accept_vision_notice、register_image、apply_import | 同意、注册、识别、预览、确认各自结果分开 |
| 设备 | register_push | regId 到本地服务，AppSecret 不进 App；平台固定android |
| 恢复 | get_recovery、recovery_evidence、recovery_seal_evidence、recovery_reconcile、recovery_confirm | 恢复期专用流程，普通业务写入冻结 |

新增读取接口的确定语义：

- **量化持仓和进度**。原 40 个请求、回执和七集合同步仍按原形状工作。新增的四个命令位于同一个 canonical v2 业务信封中，量化细节回执的功能版本为 `3`。App 先通过当前配对和纪元的 `get_execution_progress` 空参数读请求探测，再使用有 `symbol` 的 `get_holding_details` 核对持仓能力。旧中继可能拒绝新请求，探针失败时保留原业务操作。
- **reconcile_holding**。用 `basePositionRevision` 校验并发，以 `partitions` 表达数量、可叠加的限制集合和可选策略分配。分区总量须等于 `qty`。未知限制仍占数量，除交收证据明确解除外保留其他冻结。`get_holding_details` 给出独立的 `sellableBasis`、`originStatus` 和快照时点。
- **set_execution_progress**。以事项 ID 关联已持久化的计划预算，使用 `baseVersion` 和 `asOf` 检查覆盖。处理中申报通过 `reportedRemainingQty` 记录，结束需核对实际 `expectedConfirmedQty`；存在未核对成交或在途意图时保留预留。不同纪元的申报需要人工复核。`get_execution_progress` 的 `confirmedFillQty` 与 `reservedQty` 是本地账面推导，计划资金与券商资金各自独立。
- **get_candidates**：无 scanId 时固定最新一轮结束记录（包括失败轮次），无历史则 scan=null/items=[]。scanId 明确时读该轮不可变候选，按 score降序、symbol升序；分页 cursor绑定 scanId与读取快照，10分钟过期返回 SNAPSHOT_EXPIRED。页大小1–20，默认20。失败轮次不得偷偷换上一轮；用户显式查看旧 scanId 时 historical=true。候选中的来源时间/失败状态与该轮一致。
- **search_symbols**：按代码或名称检索有效证券主数据，按 symbol升序，每页≤20；不替用户选择第一个歧义结果。分页同样固定查询与10分钟读取时点。watch/unwatch须再验证支持范围。
- **get_chart**：`timeframe` 支持 `1d`、`1w`、`1mo`，缺省为日线并保留原回复形状。周线、月线回复显式带同一周期，由该周期全部已知交易日的同口径完整日线合成，日期为最后一个交易日。`adjustment` 为 `none` 或 `forward`，`beforeDate` 为排他上界。每页按日期升序，`nextBeforeDate` 为本页最早日，最多 20 根。缺失时 `candles=[]`、`dataStatus=missing`。每点保留十进制 OHLC，`source/asOf` 对应组成日线的证据及交易时段。
- **get_quote_status**：最多读取 20 个证券的报价、时间口径、来源、可用性和交易状态。市场时段由已观察交易日历确定。快照 `asOf` 为供应商的快照有效时点，`timeBasis=snapshot`。休市、过期、缺报价、供应商限流或网络失败独立显示。当日停牌或复牌只在存在已验证的当日竞价规则证据时给出。App 根据 `get_status` 中的 `get_quote_status` 能力启用此版本的报价和周期控件。
- **get_history_coverage**：无业务参数。App 根据当前纪元的 `get_status.protocol.supportedCommands` 启用读取。返回全市场不复权日线策略范围的供应商、实际覆盖起止、目标交易日、最近覆盖日的观察数和应有数、累计证券日及冲突数。`checkedAt` 为工作台收到本机内核状态的时间，`updatedAt` 为覆盖档案最近更新时间。内核暂不可用时可保留有日期的上次覆盖，缺证据用空值表示。此读出独立于持仓报价和策略准入。
- **get_logs**：只读脱敏诊断文本（每条≤1000字符、每页≤20），cursor固定查询时点/排序；不能返回原始命令、持仓明细、token或图片。App 本机日志自行脱敏，与本地服务日志分别标明来源。
- **get_task_actions**：按taskId读取创建/提醒/稍后/处理/忽略/过期/风险补证操作记录；按at降序、actionId升序，每页默认20/最多20，cursor固定10分钟读取快照。返回事件时间、原因、clientMsgId及当时version/actionVersion；自动事件clientMsgId=null。App按实际已同步记录提供离线查询，不能靠当前Task反推历史动作。
- **set_settings**：v2级别模式固定 critical=full_screen/warn=sound/info=visual；用户可调整夜间时段、criticalAtNight和pushEnabled。Android权限来自系统回读，不在本地服务伪造。

读请求重试也返回首次读取结果。展示前核验须生成新的 clientMsgId，从发请求到使用响应≤5秒；超过就重新 get_task。catalog 中 ackTimeoutMs 只是 UI 等待阈值，超时显示“等待回执”，不等于服务端失败；普通重连可原键重发；incarnation变化先get_command_status和恢复核对。

chat成功ack仅表示接受，后续reply按 requestId=clientMsgId关联；30秒未得到最终reply显示仍在处理/不可用，不拼凑答案。sync的业务页按 ack中的pageEventId关联；后续事件可先于ack到达，App暂存等待关联。register_image与import_result按importId关联。scan_now完成ack与scan_result的Scan内容一致。


## 6. 快照与并发

首次 sync 的 envelope.serverEpoch/data.serverEpoch 均可null；其他允许恢复期读取也可未知epoch。写命令两处epoch必须相同且等于当前服务端epoch。bootstrap通过已认证local端点的、关联当前主动sync的ack/页学习epoch，不能从任意迟到推送自行切换纪元。

snapshotId固定一次一致读取，snapshotSeq为该时点的业务序号；TTL10分钟。首次sync不传snapshotId/pageCursor，续页必须同时传两者；过期整组作废重新开始。ack始终指出该页pageEventId，且ack.result.requestId等于本次sync命令的clientMsgId；同页已有事件重发保持原事件ID和内容，即使另一次请求用了新clientMsgId，不能改该事件原requestId。App用当前请求的ack及pageEventId关联冻结页面，不要求页面requestId等于本次续页请求ID。

快照集合固定为 tasks、positions、executions、watchlist、imports、valuationPoints、adjustments。每页保留全部集合键，无本页记录则[]；**总对象数≤20**，不是每集合各20；还须满足64KiB。page0带manifest和meta，后续两者为null。meta含analysis/settings/visionNotice/valuation/positionRevision。

各集合在固定快照内按自身主键ASCII升序（tasks:taskId，positions/watchlist:symbol，executions:executionId，imports:importId，valuationPoints:pointId，adjustments:adjustmentId），按上述集合顺序装页。manifest含所有七集合及meta的 count/sha256；hash是该集合完整排序JSON数组的TD-C14N-1摘要；meta按单元素数组算。空集合仍有count=0和`[]`摘要。

App持久化暂存，收齐页、校验身份/epoch/snapshotId/seq、连续pageIndex、集合数量/hash和尾页hasMore=false后，才原子替换当前业务缓存。不得将某页空集合解释为删除当前所有数据。切换快照期间按eventId缓冲增量，之后按每对象版本应用快照时点以后的事件；无法证明完整性则重新sync。

已有task/scan/import事件用于及时展示；**任何成功写ack后App发起一次合并去抖的sync刷新其他集合**，重连/回前台也sync。在线可见且没有消息更新时每30秒sync；后台不因此预排提醒。这条规则覆盖持仓/设置/关注池等没有独立增量事件的更新，避免三端各自假设对方会刷新。


## 7. 导入、提醒和恢复的跨字段约束

JSON Schema只检查结构；以下条件必须在服务端业务测试和App集成测试执行：

| 场景 | 必须行为 |
|---|---|
| act实际成交 | side/price/qty/executedAt四项全有或全无；仅risk允许全无；buy/sell与事项方向一致，price>0 |
| 版本 | 提醒/补证递增version而非actionVersion；act/ignore/snooze比较baseActionVersion，终态不复活 |
| 持仓 | 0≤availableQty≤qty；未知为null；pendingLots已知时合计qty−availableQty。qty=0须confirmZero=true |
| 导入 | preview必带snapshotAsOf，confirm只引用已保存版本/hash；人工删除缺失行另需confirmRemovals；确认成本必须非空且≥0，缺成本在识别层保留等待修正 |
| 提醒 | 当前epoch、recoveryMode=false、相同reminderId、非终态、未snooze、now<displayUntil；无法核验不响。当前窗口≤60秒 |
| snooze | critical或未满两轮warn；minutes省略时默认5分钟，显式值1–5分钟，并留3分钟操作期，总寿命≤60分钟；info拒绝 |
| 文件 | Import.fileId关联本地原图，fileStatus表示可用/删除/缺失；识别成功不自动删除原图 |

当前交付采用 WS 提醒：本地调度在同一事务推进 Task、操作记录和持久 outbox；提醒只增加 version，操作版本 actionVersion 保持不变，过期终态另行推进操作版本。暂停、恢复、snooze、终态及失效窗口使旧提醒不可再展示；错过的轮次不集中补发。App 的本机“后台提醒”开关通过前台服务保留连接，属于本机偏好，不新增跨端命令，也不复用供应商 `pushEnabled`。App 重新同步后对当前有效 `currentReminder` 再走实时核验，不能从旧缓存自行生成新提醒。

明确交易规则生成的事项允许 `score=null`。这类事项要求 `direction=risk`、已核验的 `riskEvidence`、`riskEventKey` 和正整数 `eventRevision`。量化买卖事项继续使用原评分类型。生产轮次失败的 `publishedTaskIds` 可以包含独立规则证据生成的风险事项，候选仍按生产轮次状态显示。规则风险与旧评分规则继续使用同一套 task_update、reminder 与核验命令。

导入结果分两层：recognizedRows保留稳定rowId及八个识别字段的原始字符串/空值、逐字段置信度与issues，可包含负数、未知证券或非数字文本；rows仅容纳人工修正后的合法ImportRow。readyForConfirm=false时不可确认。preview必须把每个识别rowId纳入rows或显式列入excludedRows并填reason，否则IMPORT_ROWS_UNRESOLVED；手工新增行使用新rowId。缺代码不能静默丢行，原识别值不被人工编辑覆盖。成本/可用量/批次等差异由diff.changed.before/after提供完整PositionValues；不能用App旧缓存代替权威旧值。excludedRows也参与diffHash。

autoApply=true由Rust逐行生成ImportRow，不排除、不合并或补造识别行；使用真实证券主数据唯一解析并校验名称代码一致，数量正整数、成本非负必填、可用量可空但已填必须合法。数量、成本、实际用于唯一解析的证券身份字段（代码优先）及已填可用量置信度必须≥0.9，且不能含warning/error；其他行情字段不入账。空图、歧义、重复或未知证券、关键字段不合法均以IMPORT_CONTENT_INVALID整批失败。注册冻结持仓版本，提交前不一致返回IMPORT_DIFF_STALE；证券主数据不可用返回VISION_SYMBOLS_UNAVAILABLE。自动模式在一个事务内复用预览及确认并发confirmed终态事件，App须同步完整持仓后再展示成功。snapshotAsOf使用本次导入登记时刻，审计注明当前申报而非截图历史时刻；pendingLots保持null，交收未知沿用现有待对账规则。adjust_position增加可选name（非空且最多100字符），仅用于已选证券的显示名称。

Execution内嵌可空的不可变RuleSnapshot，并携带tradeDate、settlement、settlementSource与verificationScope；ruleSnapshotId非空时必须与内嵌摘要ID一致。没有规则数据时两者均null、保留警告，不提供不可解析的悬空ID。

恢复时，epoch新建、写入/扫描/提醒关闭。恢复读取和get_logs可用；catalog未标 allowedDuringRecovery 的命令一律 RECOVERY_REQUIRED，标onlyDuringRecovery的命令在正常模式返回RECOVERY_NOT_ACTIVE。业务历史消息只作证据，旧command不执行。

get_recovery首次省略reconciliationId返回当前恢复会话；本地服务启动恢复时已创建该会话，读取不创建写记录。证据上传每原记录≤64KiB、每片≤4096 bytes/最多16片；同recordId所有片的sourceType/evidenceEpoch/capturedAt/observedSnapshotSeq/hash/partCount必须一致。capturedAt为手机保存该证据的时间，observedSnapshotSeq为保存时已确认业务序号（命令尚未确认可null），evidenceEpoch是原纪元；这些元数据不改写原记录。新recordId首片就登记receiving，不等差异产生才计入门禁；完整验证后生成差异。parts同索引内容冲突拒绝，不覆盖已验记录。

Base64解码后的精确结构按sourceType选择，payloadHash对原记录的TD-C14N-1 bytes计算：command→Evidence_command完整原command信封，ack→Evidence_ack完整原ack信封；task_snapshot/position_snapshot→`{serverEpoch,snapshotSeq,capturedAt,record}`，record分别为完整Task/Position。对应定义与真实编码在RecoveryEvidencePayload/evidence-vectors.json。校验内外epoch、捕获时间/序号和sourceType一致；旧ack须以requestHash与原命令核对。未知旧主版本保留待人工核对，不能转换成当前写命令。禁止把data部分、任意占位JSON或图片当成完整原证据。

封存前必须完成App持久缓存/命令/回执证据集合收集并冻结证据上传；云无历史，不存在IM高水位。无receiving/invalid记录；manifestHash对所有已验记录`{recordId,sourceType,payloadHash}`按recordId排序数组规范化，recordCount相等。空清单也要显式recovery_seal_evidence。校验失败的记录不得自动丢弃以凑封存；无法恢复原证据时保持门禁并报告恢复失败。

recovery_reconcile每批最多20个决定和20个持仓快照，总信封仍≤64KiB；record必须携带ExecutionInput及App预分配的newExecutionId，positions.resolvedExecutionIds可引用这个同批ID。本地服务验证全局唯一，遇到他记录占用则RECOVERY_EXECUTION_ID_CONFLICT；重试同命令仍幂等。回执recordedExecutions返回itemId→executionId映射。included必须有可核验记录或与本次持仓resolvedExecutionIds关联，discard_intent仅针对未执行意图。每次新增证据、差异或对账进度变更推进reviewedSnapshotSeq并撤销封存；客户端可先对账，最后封存，再recovery_confirm。确认必须在同一事务验证封存有效、全部差异关闭、版本匹配；缺片即使差异空也不放行。

2026-11-15用户确认的恢复规则：暂停/恢复、设置、档案、设备登记、关注、扫描/对话受理、视觉告知/识别受理/取消、文件上传完成/删除/传输取消、忽略/稍后等非成交操作，使用 `archive_operation` 人工核对归档。保留恢复后的当前业务状态，不自动重放旧命令，不以旧成功ack覆盖当前状态。决定必须引用该差异全部已验证证据并填写非空说明，不得携带execution/newExecutionId/taskResolution；归档仅持久保存证据及人工决定，推进恢复版本并撤销旧封存。恢复完成后用户按需发起新的设置操作。成交、act、持仓调整、导入确认及恢复成交记录不允许用该决定跳过核对；`record` 必须有与该差异关联的成交命令或成交结果证据。原图复核门禁仍独立生效，归档delete_file证据不能使隔离原图自动可读。此变更为发布前v2契约修订，三端须更新相同快照；旧App不得把未知决定默认为included。


## 8. 版本与验收

未知主版本隔离并提示升级；未知命令/状态不执行写入或提醒。get_status.protocol.major=2，并只宣告实际已实现supportedCommands。破坏性变更升major；增补字段/命令也同步schema、样例和三端消费说明。

各端先用fixtures开发：云端假端点测连接/路由，本地命令驱动测事务/状态，App Repository注入测各屏状态。`python contracts/validate.py`只验证契约及有限故障参考模型，实际磁盘故障、Android后台、网络和供应商能力必须另验。
