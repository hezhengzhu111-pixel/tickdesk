# A 股量化决策规则 v3 草案

日期：2026-11-15。状态：用户已以“开发吧”批准作为开发依据，正在实现；新规则尚未部署或正式启用。文件名保留 draft 以便历史链接继续有效，研究参数和真实策略准入仍须按证据验证。

用户最新要求：先系统理顺符合 A 股交易制度与交易逻辑的量化规则，再详细设计 AI；AI 后续须独立综合财报、价格、行业、公司及其他相关信息，不能限于解释量化信号。本文件用于下一步设计评审与实现，不宣称覆盖所有未来市场事件。

## 1. 适用范围与文档关系

- 主线为日线波段；短线和中长期各有独立周期、入场、退出、评分、验证及持仓来源。保守/激进是风险档案，不代表短线/长线。
- 支持范围沿用当前工程的沪深主板、创业板股票及明确接入的 ETF。证券主数据、权限或规则不明时不猜测准入；不自行扩展北交所、科创板、融资融券、衍生品或券商自动下单。
- 当前行为基线仍为[决策流程 v2](../03-决策流程与规则.md)及 canonical v2 契约；本草案中标明的变更在正式确认、版本化和测试前不改变运行服务。先前[量化与 AI 设计](../superpowers/specs/2026-11-15-quant-ai-analysis-design.md)中与本文件冲突的后续方案，以本文件作为新提案，不能把旧实现与新提案混写。
- 决策分五层：**数据是否可信 → 策略是否成立 → 持仓是否适用 → 当前能否执行 → 是否需要通知**。只有用户回填的实际成交改变成交账本；操作建议、点击查看和预测均不等于成交。

## 2. 交易制度与规则版本（EX）

规则来源应绑定交易所、品种、板块、证券状态和有效日期。沪深当前 2026 版规则均含交收、交易时段、数量、价格与涨跌幅条款；实现还须核对例外和暂缓实施内容，不能只按文件年份套用。[上交所现行规则及附件](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20260424_10816492.shtml)、[深交所 2026 年规则](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)

| ID | 必须遵守的工程规则 | 缺失或特殊情况 |
|---|---|---|
| EX-01 交易日 | Asia/Shanghai；采用交易所日历，区分休市、临时停市、证券停牌 | 周末/假日不算 T+1；日历未知不猜解锁日 |
| EX-02 T+1 | 股票当日新增持仓不计入当日可卖；旧底仓单独核对 | 有底仓不意味着新增批次也可卖；可卖未知不等于已知为零 |
| EX-03 品种差异 | ETF 按真实品种的 DayTrading/settlement、数量及价格规则判断 | 不把 ETF 全部当 T+0，也不把股票规则机械套入 |
| EX-04 时段 | 开盘集合竞价、连续竞价、午休、收盘集合竞价及已接入的其他方式分开 | 扫描时段不代表当前可交易；未建模的竞价/盘后方式只观察 |
| EX-05 涨跌停 | 用当日原始参考价、有效涨跌幅、最小价格单位计算/校验 | 历史 ST、上市初期、无涨跌幅限制、除权日逐日处理，不写死所有股票同一比例 |
| EX-06 数量与报价 | 按品种校验买入单位、零股卖出、单笔数量和报价单位/有效范围 | 规则不全不给可执行数量或确定价位；仍保存用户申报的实际成交 |
| EX-07 成交限制 | 区分已停牌、缺报价、价格限制、排队/流动性不足和未知 | 涨停不必然买不到，跌停不必然卖不掉；只有证据支持才标不能成交，其他标成交不确定 |
| EX-08 规则时间 | 历史研究使用当时有效制度；当前展示用当前制度 | 新制度不回写旧成交有效性；保留规则版本与数据来源 |

权限未知时可以展示研究资料，不宣称用户已具备相关交易权限。真实券商可卖、冻结、挂单与账户余额未接入时，不由本地推算冒充已核验账户事实。

## 3. 分离计算、检查、报告和通知（TM）

1. **TM-01 五分钟检查**：保留原调度窗口，但先识别实际市场阶段。检查输入是否更新、持仓风险及原候选有效性；不是每五分钟重算所有日线，更不触发固定频率的 AI 或买卖通知。
2. **TM-02 日线策略**：新完整日 bar 最终可用后计算。盘中使用最后已完成 bar 的策略结论；新现价只用于执行条件/盘中保护规则。不能用未完成日线的“收盘突破”提前证明收盘条件成立。
3. **TM-03 发布时机**：盘后完整结果形成次日观察清单，下一合法可操作阶段重检报价、缺口、风险及数量。午休、竞价之外或已收盘时，不把观察清单写成“现在可以交易”；适配未覆盖的竞价不假装下一成交价已知。
4. **TM-04 独立周期**：短线用明确分钟 bar；中长期按自身日/周/月决策点。周期不同的反向信号不能直接互相抵消或改持仓策略。
5. **TM-05 数据指纹**：相同完整 bar、参数及数据版本复用计算；抓取时间和 scanId 变化不使原信号变成新机会。历史修订可重算并记录差异，但不补发过期历史操作。
6. **TM-06 发布期限**：沿用现有扫描计算/8 秒绝对发布预算；不等外部模型或长研究作业。重叠轮次不积压补发，暂停/恢复、纪元变更继续有提交时门禁。

7. **TM-07 盘后数据**：最终日 bar 在 15:05 后才到齐时，由独立、可重放的盘后观察作业计算研究清单；不扩展“当前可操作”窗口，也不伪造 15:00 已知。若作业未运行，下一合法轮次先补算可得的完整 bar 再重检当前条件，不能补发昨日操作。
8. **TM-08 通知后才可能执行**：新日线信号的首次操作阶段默认是次一交易日实际支持的连续竞价时段，且晚于输入可得、计算、发布和合理的人为响应时点。未建模开盘竞价时，严格准入回测不能记成 `open_t+1` 开盘价成交；需要相应分钟/报价数据，采用预先固定的通知/响应延迟模型和其后可成交价。只有日线的数据可作粗略对照，须标为执行时点未验证，不进入严格正式批准。

闭市期间可保存公告、事实和风险背景，并在下一个合法检查点处理；首期不新增全天候操作推送。若后续启用盘后重大事实提醒，必须是独立版本的风险告知策略，说明当前不可操作且遵守用户暂停/静音；不能借盘后作业绕过现有门禁。

五分钟风控存在检测间隔和通知延迟，应显示最近检查时间，不称为实时止损或保证在指定价成交。

## 4. 数据可用性、证券池和指标（DT）

| ID | 规则 |
|---|---|
| DT-01 时点 | 保留 bar 起止/最终状态、公开时点、系统可得时点、抓取时间、修订和来源；决策不得读取未来公告/修订 |
| DT-02 历史资格 | 上市、退市、ST、停复牌、股本、行业/指数成分按当时状态读取；不能用今天的证券池筛全部历史 |
| DT-03 价格口径 | 技术计算声明复权方式及锚点；成交、资金与限价用实际原始价格；公司行为同步核对数量、成本、阈值和来源 |
| DT-04 缺失 | null、不可计算、无信号、执行失败分别存储；缺换手/股本不补零，不静默跳过滤/重配权重 |
| DT-05 数据质量 | 重复、乱序、缺 bar、异常跳变、单位冲突、停牌缺值及供应商分歧有明确校验；不能自动删除大涨跌掩盖真实风险 |
| DT-06 窗口 | 每个指标注明预热长度、是否包含当根、有效 bar 还是市场交易日；停牌不机械前填成有成交的平盘 |
| DT-07 来源 | 不用抓取时间冒充市场时间，不写固定假供应商名；未知来源/缺字段写入影响范围 |
| DT-08 独立失败 | 行情失败只阻止依赖该行情的结论；已核验官方风险可以独立处理，不被“全部策略失败”吞掉 |

初始正式新增买入池建议排除 ST/退市整理、上市观察期不足、长期停牌/刚复牌缺必要数据、规则未知及不足预热的证券。排除只针对新增风险，已有持仓仍必须监测。观察期、成交额等阈值是版本化策略参数，不能作为普适盈利结论。

## 5. 策略体系与入场判断（EN）

### 5.1 完整策略，而非指标投票

新版提案取消“所有买卖统一满足 3/2 个策略 ID”作为唯一准入方式。每个已批准策略必须有完整的市场/个股条件、入场触发、失效条件、退出、周期、风险和数据声明；满足一套完整规则才能形成候选。是否需要多源确认由该策略明确配置。多个相似均线指标不算多份独立证据，原始命中数量及家族数量仅如实展示，不能宣称成功概率。

这是相对 v2 的业务语义变更，需用独立规则版本研究/影子比较；原 3/2 的 legacy 规则继续可读，不静默切换已批准清单。分数用于同一已校准范围内的排序，不把不同组、资产或股票池的相对分直接比较。

### 5.2 三组策略的明确职责

| 组 | 优先策略与必要条件 | 退出逻辑及限制 |
|---|---|---|
| 日线波段 | 趋势突破、趋势回调、压缩突破、同池相对强弱；完整日线、足够预热、市场/行业环境和流动性；避免追离计划区间过远的价格 | 持仓绑定的趋势失效、止盈/跟踪保护、初始保护、时间退出；当日新仓的保护也受 T+1 约束 |
| 短线 | 明确定义的量价/反转/事件策略；分钟覆盖、成本与成交时点可验证 | 普通股票不得以当日买入当日卖出为策略成立前提；不能把 A 股低吸高抛 T+0 示例作为新仓可执行策略 |
| 中长期 | 质量/估值、收益与现金流、相对强弱和适用 ETF 轮动；可知时点财务、公司行为及历史池 | 按财务假设失效、调仓日、估值/趋势规则与持仓风险复核；不被短线噪声直接强制退出 |

行业及市场环境属于量化可以使用的数值输入；无历史行业成分、基准或必需宽度数据时，相应策略不可评估，不能让 AI 即兴补出环境状态。极端行情下的新买入限制、组合降风险均为事前配置规则，且卖出能力仍逐仓核对。

### 5.3 首批可计算的研究基线

以下数值是用于复现和比较的研究参数，不是正式推荐，须通过后文准入。每个参数及表达式归入源码/配置 hash，不能根据最终测试集反复选参。

- **EN-B1 日线突破**：以完整 bar 的收盘 `C[t] > max(H[t-L:t])`，窗口排除当根；趋势门禁和量比阈值分别配置。研究起点 `L=60`、`MA20>MA60`、收盘在 MA60 之上、当日量/前 5 个有成交完整日均量 ≥1.3。历史 OHLC 极值与最高收盘分开命名。次日现价超出预设追价距离/跳空容忍则保持观察，不追认昨日价可买。
- **EN-B2 趋势回调**：先满足版本化趋势条件，再满足相对均线或 ATR 的回撤范围及恢复条件；触及均线本身不构成支撑确认。研究中分别比较“收盘重新站上参考线”和“形成完整反转 bar”的规则，禁止将两套结果挑优拼接；反转前的持有风险和下一个执行点均计入。
- **EN-B3 相对强弱**：在当日历史可交易池内，用预先固定的回看/跳过区间计算相对收益排名，再过流动性、市场/行业和风险门禁。研究可比较 63/126 bars 与跳过 5 bars 的配置；每次尝试记账，不把最优配置伪称唯一预设。
- **EN-B4 波动压缩突破**：压缩窗口先于突破 bar，按历史窗口自身价格尺度计算；需要明确波动收缩、价格突破与量能条件。不得使用突破后的大阳线缩小此前振幅比例。

25 个旧模板按审计逐个修正或重命名，不以“模板全部能加载”代替策略有效性。涨停接力/反包等高限制策略留在独立研究范围，须证明历史封板、断板与恢复时序和可成交性后才可申请准入。

## 6. 买入前的确定性检查（BUY）

检查顺序固定，逐条保留首拒原因与相关证据：

1. **BUY-01** 已批准版本、支持市场、账户权限/规则范围、必要数据及时点通过。
2. **BUY-02** 对应策略的市场环境、证券池、趋势/量价/其他入场条件完整成立；必要字段失败不降低阈值。
3. **BUY-03** 停牌、官方硬风险、数据冲突及证券事件按固定规则处置；软风险解释与硬禁入分开。
4. **BUY-04** 新鲜原始报价位于计划条件内；过大跳空、远离入场区间、追涨、价差/流动性或可成交性不足时观察/拒绝，不用旧收盘价显示可执行机会。
5. **BUY-05** 检查已有持仓、尚未解决的退出、未确认成交和计划敞口；新增、加仓、减仓不是同一种动作。存在未解决保护性退出时不发同标的加仓建议。
6. **BUY-06** T+1 锁定、隔夜缺口、费用滑点、单笔风险、单标的/行业/相关资产集中度、组合计划额度通过；无可信输入只给无数量观察。
7. **BUY-07** 同一来源事件去重、全局冷却及当日新买点额度通过；候选不为凑额度越过质量门槛。

新增持仓和加仓都增加风险。加仓必须由策略显式允许、有独立原因且预算重算；默认不因下跌或浮亏自动摊薄成本。持仓之外的候选可继续研究，但未通过门禁不包装成可执行买点。

## 7. 仓位与资金（RS）

- **RS-01 已知范围**：总资产、现金、负债、冻结及未记成交未知时，不给账户级精确仓位/收益或“还能买多少”。用户设置的计划预算不等于券商可用资金。
- **RS-02 数量计算**：可追溯风险预算、入场参考、止损参考、成本与规则完整时，计划数量同时受单笔风险、单标的敞口、剩余计划金额和流动性容量限制，最后按交易单位取整；取整为零则观察。计算不能承诺实际止损损失上限。
- **RS-03 组合约束**：全账户已知范围内检查行业及相关风险集中；资料不全则声明只覆盖已记录持仓。跨策略的同标的风险不拆开绕过上限，ETF 与成分股重叠暴露在有数据时计入。
- **RS-04 退出优先**：持仓保护与已有退出先处理，新增风险后处理；日买点额度不压制退出/风险。卖出提示、未成交订单及尚未确认的卖出不能释放计划现金。
- **RS-05 预算事务**：预留、释放、成交回填和状态变化以幂等事务提交；普通重启不丢预留，恢复旧备份需要纪元与人工对账。
- **RS-06 参数变更**：不靠 AI 或近期少量胜负自动调大仓位、放宽阈值或提高风险；新参数记录版本，需重新验证适用范围。

### 7.1 人工执行进度与部分成交预留

新版首期新增**用户申报的执行进度**，不接券商或代发委托。执行意图记录稳定 ID、关联证券/计划、申报数量、累计已确认成交、未完成数量、进度来源及更新时间。进度区分未开始、用户声明处理中、部分成交、已结束/余量已撤、结果未知；声明“在处理”不等于券商接受订单，“撤单”也须用户确认结果，不能用点击动作推断成功。

- 仅有未开始计划、没有申报中的执行/未对账成交/在途回填时，事项忽略或过期可释放未使用的本地计划预留；这不代表实际券商资金已释放，未申报外部操作仍需用户对账。
- 用户声明已提交或开始处理后，通知过期/忽略不释放执行中的余量。部分成交仅转换对应已成交敞口，剩余预留覆盖仍有效的未完成部分，不能一笔成交就把全预留转为已成交或释放。
- 用户确认全部完成、未成交结束或余量已撤并与成交记录核对后，才关闭剩余预留。结果未知或记录冲突时保留不确定敞口并要求对账，不能拿它支持新数量建议。
- 同一执行意图跨通知、重试和新提醒共享同一预留；新的独立计划用新 ID，但全局剩余额度统一核对。迟到的真实成交始终留存，超出预留形成差异，不能改小成交来强行平账。

该进度模型需 canonical 请求/回执与 App 明确交互；旧 `act/record_execution` 仍是成交事实，不能兼任券商订单状态。无新能力的旧 App 继续事实登记，遇到部分成交/余单不明则进入保守对账，不自动释放后继续推荐。新版预留采用独立规则版本，避免改写旧记录语义。

## 8. 持仓状态与退出（POS / EXIT）

内部持仓/退出状态独立于 App 通知卡的 `pending/reminded/acted/ignored/expired`，不向旧 schema 偷加状态。

| 状态 | 进入条件 | 下一步 |
|---|---|---|
| 观察 | 有研究结论，无确认持仓/未满足买入门禁 | 不预测成交，继续检查 |
| 持仓待对账 | 有真实成交但数量/可卖/来源未核对 | 留存成交与风险，停止依赖未知数量的操作建议 |
| 新增数量受限 | 已确认 T+1 当日买入部分 | 持仓保护持续运行，受限数量不能卖 |
| 持仓可卖 | 可信可卖数量大于零 | 按适用退出规则计算范围，仍需核查成交条件 |
| 退出受限 | 退出成立，但 T+1/停牌/可成交性等受限 | 留存退出观察、理由及复核点；不假成交、不重复催不可执行动作 |
| 退出可操作 | 退出成立且必要规则/数量/行情通过 | 发一次适用提示，等待真实回填；不自动下单 |
| 部分退出 | 已记录实际部分成交 | 更新剩余数量、可卖和风险；未成交部分仍监测 |
| 已平仓 | 对账后确认数量为零 | 关闭对应持仓退出观察，真实重新入场才开启新周期 |

### 8.1 退出由持仓计划定义

- **EXIT-01 保护性退出**：初始止损、跟踪保护或已配置重大风险一旦有效触发，按规则生成风险/退出意图；不等待其他入场指标凑够 2/3 次共振。
- **EXIT-02 策略正常退出**：原入场逻辑失效、趋势退出、止盈或最大持有期，由该持仓所绑定策略的独立退出规则判断。新版提案不再统一要求多个其他策略同时卖出。
- **EXIT-03 优先与合并**：同一范围的保护退出优先于普通退出和新增；多个退出原因合并证据，不把同一数量累计卖多次。目标数量只能按明确的减仓/全退规则计算，不能一律取全部持仓。
- **EXIT-04 止损时钟**：盘中触发还是完整日线收盘触发必须事先声明；不能事后挑更有利的价格。跟踪保护是否随有利价格单向收紧明确配置，不能为了回避触发临时放宽。
- **EXIT-05 持有期**：以确认成交时点和交易日历计算，部分买入的计算口径固定；不能从信号发布时间算已经持有。期限到达是重新检查/退出意图，不保证成交。
- **EXIT-06 受限时持续性**：普通趋势退出可在下一个确认点按规则失效；触发后持续有效的保护规则保留意图，直至实际退出、规则允许的解除或明确人工处理。缺数据不是解除依据，反弹也不自动撤销规定锁存的止损。
- **EXIT-07 混合来源**：按证券汇总的台账保留策略来源证据。缺少唯一归属时仅提供无数量观察；不能用今天短线入场的止损价清掉旧波段仓，更不能用 FIFO 臆造策略归属。

最小归属证据为成交 ID → 执行意图/事项 → 进入时策略组、策略版本和明确分配数量。加仓/部分退出须有明确对应计划；无法确认归属的卖出或人工快照只更新可核对的证券总量，剩余策略分配降为未知，不能把原分配继续当精确数量。旧手工持仓若没有该关联，保留为“未分配”；只适用明确的证券级通用保护及事实风险。用户可明确分配已确认持仓，但那是有审计的人工归属，不伪装成历史成交自动识别。

### 8.2 T+1 与执行受限闭环

1. 当天新买入后反向信号成立：判断适用规则，显示“退出条件成立 / 今日新增部分 T+1 受限”，保留依据，不发该数量可立即卖出的指示。
2. 有旧可卖底仓时，最多在可信可卖量及规则适用范围内处理；总持仓不能替代可卖量。买入日期/规则/日历不足时显示待确认。
3. 下一实际交易日复核：确认交收记录、剩余持仓、可卖、行情和原退出规则。原普通信号失效则归档；持续保护继续跟踪，不机械照搬昨日价格。
4. 停牌、跌停排队或流动性不足可能继续延迟；T+1 到期不等于必能成交。任何展示的最早可卖日都标明推算或确认来源。
5. 使用 `pendingLots` 管理日期与数量的交收记录，覆盖跨假期、多笔买入、部分卖出、更正与公司行为；这不等于增加完整策略分批成本账。不能在每天零点无条件解锁全部数量。
6. 通知卡到期/忽略不删除持仓风险，也不自动重开旧卡。后续首次出现经过复核的可操作阶段可生成有来源关联的新提示；这不是把原官方风险事件的修订号加一。

### 8.3 可卖依据与其他冻结

可卖依据分为用户确认的券商快照、本地已知记录推算和未知，始终附数据时点。快照后的推算仅在以下条件全满足时可作为**本地计划上限**：快照与成交连续且无对账差异，股票/品种交收及日历已核实，公司行为已处理，全部用户已声明执行进度已计入，其他冻结已知。它不证明用户未申报的券商操作不存在，界面必须标明本地推算。快照过期阈值触发、未解成交、外部操作/冻结未知、恢复旧备份或公司行为缺失时，数量建议回退待确认；快照时效是版本化数据质量配置，不让模型临时决定。

跨交易日先使昨日的可执行性校验失效；在下一支持的操作阶段重新校验日历、交收批次、连续成交、公司行为、冻结、执行进度及快照时效。全部通过时可重新生成当日**本地推算上限**，不要求机械地每天重录券商快照；任一必要项不确定才保持待确认并请求新的有效信息。重新推算不会把其来源升级为当日券商确认。Q25 中的 500 仅在这些检查通过且无其他限制时，才进入新的本地上限。

总量需要区分可卖、T+1 待交收、其他受限及受限原因未知，且每个数量只计一次。若同一数量有多个限制，只有相关限制全部解除才可用。例：总量 1500 = T+1 500 + 其他冻结 300 + 可卖 700；次日处理交收只可能释放 500，不能释放仍被冻结的 300。冻结原因或到期未知时不推算释放时间。

当前 v2 的 `pendingLots` 不足以表达全部上述分解，不得把全部 `qty-availableQty` 填成 T+1 批次。新版需显式建模并协调契约；旧快照无法区分时保留已确认可卖量，其余受限来源未知，不做自动日切解锁。未知不能强行通过“合计相等”校验变成伪造的交收事实。

## 9. 信号冲突、重复与提醒（EV / NT）

| 场景 | 明确处理 |
|---|---|
| 同周期买卖同时成立 | 先检查保护退出，再检查本持仓正常退出；存在未解决退出时抑制新增，不把两者相减成中性 |
| 不同周期方向相反 | 分组展示，与持仓来源匹配；不能无规则净额抵消，归属不明不给数量 |
| 多个同族策略命中 | 保留逐条依据，去除重复贡献，不提高为独立证据或盈利概率 |
| 持续命中一小时 | 五分钟检查十二次仍是同一事件；不重复买、不因冷却结束又发一次 |
| 无数据后恢复 | 缺数据不是信号失效，不因此制造新的上穿/下穿；恢复后核对持续事件状态 |
| 新 bar 或同公告重抓 | 可更新分析/审计，不自动产生新操作；同事件事实修订按实质变化处理 |
| 同时多个买点 | 同组用冻结可比较分数排序；跨组用明确的已批准优先级与全局风险预算，不比较未校准分数 |
| 手动扫描/恢复扫描 | 不绕过数据、去重、预算、窗口及暂停/纪元门禁 |

本版采用明确的保守冲突政策：**同一证券上任何已批准且适用于真实持仓的未解决退出意图（保护或普通）均抑制该证券各组新增/加仓**；其他证券不因此一律停买。普通退出经原规则确认失效、实际完成或人工处置且持仓已对账后才解除；通知过期不等于解除。仅研究/影子输出、没有适用持仓的卖出信号以及证据不足的模型观点不触发此抑制。各组可以有相反研究观点，但不会同时给用户同一证券相冲突的新增/退出操作。

**新版提醒提案**：普通新机会一次通知；持续相同信号只更新页面。退出受限显示原因与复核时点，默认不每三分钟催卖。可操作且尚未确认的紧急风险，可按独立策略再提醒一次；后续持续重复应为显式可配置能力，不跟随每五分钟扫描。用户确认已知、忽略、过期及恢复都有持久幂等语义；风险未解除时仍在持仓页可见，通知确认不代表风险解除。

上述频率区别于当前 critical 的第 5 分钟后每 3 分钟重复；须作为新的提醒策略版本协调本地、App 和契约验收后才启用。既有事项沿用其创建时规则，不静默重置提醒次数、有效期或动作版本。30 分钟是当前通知卡操作期限，日线策略观点、风险事实和持仓监测不能跟着 30 分钟到期消失。

## 10. 实际成交、对账和收益（LD）

- 系统只提出观察/操作参考。用户应在券商完成交易，再回填实际时间、价格、数量；只点“已处理”或通知送达不能改变持仓。
- 分笔/部分成交、取消未成交、交易后漏记、重复回填、旧记录更正和人工快照都必须有明确路径。行情后续达到某价不能推断用户已成交。
- 真实成交与本地规则冲突时保留事实并提示对账；不因本地判断跌停难卖或可卖量不足而删除用户成交。相同幂等键不得重复入账。
- 现金流、总量、可卖、受限量、费用与持仓版本分别核对；成本缺失、费用未记、来源不全时，不计算看似精确的净收益。
- 计划风险、回测账户和实际已记录交易分别展示。无成交的过期事项不能自动算亏损/误报，也不能以事后上涨算盈利/漏报。

## 11. 回测与准入（BT）

1. 冻结策略、参数、数据、证券池、交易制度和基准；保留所有研究尝试，含失败。历史财报修订与退市证券必须按可知时点处理。
2. 事件顺序为可执行的时间顺序，开盘前只能用当时已知的数据和现金。收盘卖出不能为同日开盘买入提供资金。
3. 股票新买仓位当日不能卖；保护触发进入受限退出。跳空按实际可成交口径、停牌/涨跌停及容量按证据/披露的模型处理，不能以止损价保证成交。
4. 费用、最低佣金/税费适用期、滑点、整手、部分成交、现金不足、同日多信号竞争和公司行为有独立测试；不能用复权价直接当成交金额。
5. 日 OHLC 同时穿止盈止损且无分钟先后时采用预先固定保守假设；不能挑更赚钱的顺序。信号当根收盘已知后不回填到此前开盘。
6. 样本结束未能卖出仍为持仓估值与待执行意图，不假平仓。净值、现金、费用、成交和仓位守恒；已平仓交易统计与浮动收益分开。
7. 交易日 walk-forward、标签跨度隔离、训练拟合与样本外评估分开；重叠外测折不直接复利。保留最终未参与选参区间，参数敏感性与成本压力一起报告。
8. 按组比较适配基准及简单基线，披露交易数、不可执行率、覆盖、回撤、换手、持有期及市场阶段；没有有效样本时不可算，不能填零冒充失败/通过。
9. research → causal_checked → oos_checked → shadow → approved，每一步有真实可读取且散列匹配的证据。AI 生成代码、AST 通过、字符串 `validated` 或高胜率均不等于获批。
10. 合成数据用于确定性计算与三端闭环；真实可用性、容量、成本和样本外效果仍需真实数据。源码或参数变化不继承旧批准。

## 12. 参数的边界

| 类别 | 内容 | 生效要求 |
|---|---|---|
| 交易硬约束 | 日历、交收、品种范围、涨跌幅/申报规则 | 来自对应市场及有效日期，不由优化器调参 |
| 用户计划约束 | 预算、允许市场、集中度、提醒偏好 | 明确来源和版本；未知不猜 |
| 策略参数 | 均线/突破窗口、量比、回撤、止损/止盈、持有期 | 研究起点可给定，正式配置须完成准入，不运行时自适应修改 |
| 产品调度参数 | 五分钟检查、现有 30 分钟卡期限及轮次截止 | 与策略周期、AI 频率分开；变更需协调三端 |

当前代码/文档中的保守 3 条、激进 8 条新买点日限额与 60/30 分钟冷却继续作为 legacy 配置，不视为已经优化的最佳参数。新版普通卖出不再靠买入策略数量确认，但必须绑定明确退出规则和持仓；不为补空缺临时设定“看起来合理”的生产阈值。

## 13. 必测场景矩阵

| ID | 场景 | 预期结果 |
|---|---|---|
| Q01 | 同一日线条件跨十二个五分钟槽 | 重用计算，原事件持续，不生成十二个事项或 AI 请求 |
| Q02 | 未收盘大涨后回落 | 不生成伪收盘突破；已配置盘中保护按其自身时钟判断 |
| Q03 | 今日首次买入后触发退出 | 受限风险可见，可卖为零，无假卖出 |
| Q04 | 旧可卖 1000、今买 500 | 在来源和规则适用范围内可卖上限不超过确认的 1000 |
| Q05 | 节前买入/跨周末 | 下一实际交易日复核，不按自然日自动解锁 |
| Q06 | T+1 到期但停牌/跌停 | 保留受阻退出，不保证可成交，不伪造止损价 |
| Q07 | 前日普通退出信号次日失效 | 按规则归档；持续保护规则单独按其解除条件处理 |
| Q08 | 单个持仓保护规则触发，其他策略未命中 | 不等待共振，风险可见，执行仍受数量/交易制度限制 |
| Q09 | 两组持仓混合、部分减仓后归属不明 | 无数量观察，不猜 FIFO 策略归属，不重复计算退出量 |
| Q10 | 同时有退出、加仓及多个买点 | 保护/退出先处理；未解决退出抑制新增，预算不重复占用 |
| Q11 | 收盘卖 A、同日开盘欲买 B | A 的钱与仓位槽不能提前资助 B |
| Q12 | 末日无法卖/缺最终价格 | 未平仓及估值缺失分别披露，成交列表不假闭合 |
| Q13 | ETF 规则/换手未知，上市天数缺失 | 不默认 T+0、不补零打分、不静默放行 |
| Q14 | 除权分红送股前后 | 数量/价格/阈值口径可核对，不制造假跌幅或假止损 |
| Q15 | 同期财报修订、历史 ST/成分变化 | 旧截止点只能见旧版本，无未来池/最新股本泄漏 |
| Q16 | 暂停中已算完、恢复旧备份或断网重连 | 提交时门禁有效，旧代际不发布/补响，不重复入账 |
| Q17 | 真实成交与本地可卖/限价推断冲突 | 成交保存，对账可见，不篡改实际价量 |
| Q18 | 当前价远离昨日计划区间 | 不用昨日价诱发可执行提示，等待新条件或观察 |
| Q19 | 全策略失败但官方风险证据完整 | 量化失败如实记录，独立风险可见且遵守全局暂停 |
| Q20 | 无资金/不完整持仓、无费用 | 不给账户精确仓位、可买数量或净收益 |
| Q21 | 同一风险终态、重复公告、卡过期 | 不复活旧卡；风险背景可见；真实新阶段有独立关联 |
| Q22 | 已知受限风险持续未操作 | 不按三分钟无差别催促无法执行动作；显式提醒偏好单独测试 |
| Q23 | 零分、全缺、不同组相对分 | 零不当缺失；无跨组未经校准分数比较 |
| Q24 | 日历/时间戳错位、源中断恢复 | 缺失有具体原因，不误判新事件或重置持续状态 |
| Q25 | 总量 1500、T+1 500、其他冻结 300、可卖 700 | 交收最多释放 500，其他冻结未解除不释放；原因未知不猜日切 |
| Q26 | 计划买 1000，成交 300，余 700 仍在处理 | 只记真实 300，余量预留保留；卡过期不释放，确认余量结束后再核对释放 |
| Q27 | 旧波段 1000 与短线 500，随后未归属卖出只剩 800 | 总量据事实更新，策略余量未知；无精确策略卖出数量，无伪 FIFO |
| Q28 | 完整日 bar 15:20 可用，App 次日 09:30:08 发布 | 盘后可作观察，严格回测不能用次日 09:30 开盘价当已成交；只接受符合响应与可用数据的后续执行 |

上述矩阵覆盖当前可识别的主要制度、数据、持仓、策略和异常路径；新增策略/品种必须增加专有场景，不能把本表当永久完备证明。

## 14. 当前实现差距与实施顺序

代码审计见[策略](../research/2026-11-15-strategy-code-audit.md)、[回测](../research/2026-11-15-backtest-data-audit.md)、[AI/扫描](../research/2026-11-15-ai-analysis-audit.md)。当前已复现/查明：原始 ID 共振、入场结果重贴卖出、缺字段零分、时间戳午夜化、T+1 回填依赖对账/无完整解锁、零可卖退出直接跳过、同日资金倒序、尾部假平仓及财报修订覆盖。

推进顺序固定为：交易规则与数据时点 → 成交/持仓/可卖和回测正确性 → 入场与退出策略 → 事件去重及适用提醒 → 合成数据三端闭环 → 真实数据研究准入。AI 详细方案和接线在量化规则闭环明确之后开展，不以 AI 文本掩盖量化缺口。

涉及内部状态或提醒语义改变，先校核 canonical 契约及 App；现有字段不足时正式升级、导出三端快照并测试旧数据，而不是解析解释文字执行逻辑。新规则包不得静默改写用户已有策略/持仓/批准。当前不启动真实策略、不替用户购买数据、不改运行服务。

## 15. AI 后续范围：记录用户要求，暂不展开实现

AI 定位为**独立的综合投资研究与判断**，可以主动分析关注/持仓证券，不必等待量化产生候选。量化结果是其中一项输入。后续信息范围至少包括：

- 财报：盈利与增长质量、经营现金流、应收/存货、债务与偿债、资本支出、审计与会计异常、财报修订；单季、累计和 TTM 口径分开。
- 估值与预期：历史/同业估值、盈利可持续性及市场预期差；没有一致预期数据时不编造“超预期”。
- 价格与市场交易：近期及多周期走势、量价、波动、流动性、相对行业/指数强弱、资金类数据的定义与覆盖。
- 行业与产业链：景气、供需、价格、竞争、上下游传导、技术替代、政策和监管。
- 公司动态与治理：公告、订单、产品/业务、并购重组、股东增减持、解禁、质押、回购分红、诉讼处罚、关联交易、管理层变化。
- 市场环境：宏观、利率/汇率、政策、市场风险偏好、风格和系统性风险；境外因素仅在与业务/估值有关时引入。
- 催化剂与情景：后续可核验事件、利多与反证、短中长期适用性、基准/乐观/悲观情景、未知项及结论失效条件。
- 用户持仓背景：已知成本、期限、策略来源、组合暴露与流动性约束；未知账户信息不补造。

输出应有独立观点、论据与反证、关键风险、时间尺度、情景条件及信息完整度。可以明确指出“量化信号偏强，但综合研究认为基本面/估值/事件风险不支持”，不强行与量化一致，也不把模型观点偷偷算入量化分数。研究观点、确定性硬风险及用户实际操作分别留痕。具体数据源、更新频率、模型工具、界面和冲突呈现待量化规则整理完成后再详细设计。
