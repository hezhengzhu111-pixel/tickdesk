# 本地服务设计：量化决策、人工台账与可靠通信

版本：v2 设计，2026-11-15。本文规定目标实现，未声称业务服务已建成。配套：[云端设计](cloud-service.md)、[App 设计](android-app.md)、[v2 契约](../../contracts/v2/)、[量化与 AI 参考研究](../research/quant-ai-reference.md)。跨端字段、错误码、传输状态和命令参数以 v2 契约为唯一规范；本文的内部表名/模块名是待实现设计，不是现有 API。

## 1. 责任与不变量

本地服务是 TickDesk 业务事实的唯一权威，负责数据质量、策略运行、确定性风控、事项、人工申报成交、持仓对账、文件原图、消息历史和业务回执。App 管理交互、缓存和待发队列；云端只做鉴权与在线双向 WebSocket 中继，无持久业务数据库、消息历史或文件存储。

已确认：不接券商、不自动下单；原图由本地保留、用户可手动删除；App 只暂存上传队列；外部视觉服务处理图片仍需事先告知并取得授权。本地“可靠”指可恢复、可检测缺失、重复不产生重复业务效果，不承诺交易盈利、无限离线可达或终端磁盘永久不损坏。

必须保持：

1. 量化生成买卖候选，AI 仅提供带来源事实与解释；硬风险只经确定性规则拦截。AI 不能改信号方向、评分、共振数、预算或台账。
2. 事项“已处理”、消息“已收妥”与“真实成交”是三种不同事实。记录成交只代表用户申报，不代表券商验真。
3. 资金、数量、价格、成本和可用量不完整时显示未知；未知不补零，不用模拟账户现金冒充真实账户现金。
4. 关键数据不足时不新增依赖它的候选；已经发生的用户申报成交可按范围与结构校验留痕，并转待对账，不能因为风险规则不通过就消除事实。
5. 业务更新、命令回执、版本递增和业务 outbox 同一事务提交。网络发送、AI 调用、文件传输不放在数据库事务内。
6. 历史数据修订、成交纠错、策略发布与恢复都留旧版本；重放无外发副作用。

## 2. 实现边界与代码事实

### 2.1 选定架构

采用本地业务服务 + Tick Stock Panel 内核适配器。业务服务独立进程，拥有 SQLite 与文件目录；内核仍通过 provider、仓库、指标、策略和回测管线提供数据与研究计算。两者默认仅本机监听，App 不直接访问内核 HTTP API。

比较过的方案：完全修改内核会把台账与通信生命周期绑在高冲突入口；另建量化引擎会重复数据和指标语义；独立业务服务加少量内核接线能保存既有能力并分开故障域，因此作为本设计的工程选择。它仍需要内核补充“单次冻结上下文”的薄接口，不能靠重复拉现有 HTTP 接口假装原子快照。

开发分级：策略文件/参数采用 L1；后端路由注册和只读接线采用 L2；若现有上下文无法暴露 generation、数据来源及冻结评估能力，按 L3 做最小接线。禁止继承整个 StrategyEngine、BacktestEngine、DataStore，禁止复制其管线。

## 3. 模块与进程模型

| 新模块 | 职责 | 依赖与禁止事项 |
|---|---|---|
| lifecycle / health | 单写者锁、迁移、恢复门禁、能力检查、关闭顺序 | 未完成恢复不启动扫描；健康状态不能只看进程存活 |
| kernel_adapter | 现有内核 API/新增薄接口适配、能力检查、冻结上下文 | 不直接读取供应商私有字段；不在 API 层全盘重算 |
| data_catalog | 版本、水位、来源、质量与历史可见性 | 原始输入不可原地被新版覆盖；缓存不是证据 |
| scan_coordinator | 调度、冻结输入、并行策略、有界超时、轮次落库 | 单轮互斥；到期结果不能补发成新信号 |
| candidate_policy | 范围、过滤、共振、排序、额度、冷却 | 规则纯计算，参数显式；缺字段不可按 0 分通过 |
| risk_guard | 已记录持仓约束、硬风险、预算核验 | 硬门禁在最终事务前复核；AI 无修改入口 |
| evidence / ai_enrichment | 来源包、AI 解释、OCR 草稿、超时/质量标注 | 工具默认只读；不把模型置信度当事实正确性 |
| task_service | 事项状态、提醒轮次、期限、操作版本 | 终态不可复活；通知失败不撤销事实 |
| ledger / reconciliation | 人工申报、批次、基线、纠错、估值 | 十进制、追加记录、并发版本；不下单、不推算未知现金 |
| file_service | 原图归档、块传输、校验、删除、磁盘配额 | 不接受客户端路径；不将云中继当存储 |
| command_processor | 校验 v2、幂等、执行、持久回执 | 业务拒绝也留首次回执；未知命令绝不动态 dispatch |
| relay_client / sync | 主动连云、两端收妥、重试、全量/增量业务同步 | 无云历史查询；传输 receipt 不代表业务接受 |
| research_worker | 回测、因果检查、影子结果、版本清单 | 独立资源预算、禁写业务库、禁发通知 |

主进程只保留轻量协调与单 SQLite 写入序列；CPU 密集策略/回测进工作进程，有明确内存、并行数和取消预算。实时行情回调不能阻塞等 AI、文件 I/O 或全历史扫描。队列有容量上限，优先保留命令回执、同步和重要风险事实；行情展示可合并最新值，成交/命令/审计不能静默丢弃。网络调用不持业务锁。

关闭顺序：停止新扫描/上传受理 → 取消或等待有界工作进程 → 结束当前短事务 → 保留所有未确认 outbox → checkpoint/关闭数据库 → 关闭连接。强制终止仍依赖已提交记录恢复，不依赖 shutdown 钩子才能保存。监控至少记录轮次延迟、数据水位/过期标的数、预算拒绝、待对账数量、outbox 最老未确认年龄、receipt/业务 ack 延迟、磁盘余量和最近成功备份；日志只记必要 ID、错误和耗时，持仓正文、图片、密钥及 AI 原始敏感输入不写普通日志。

## 4. 接口消费与适配契约

### 4.1 内核真实入口

本机适配器可使用已存在的 GET /api/strategies、POST /api/strategies/run、POST /api/strategies/run-all、GET /api/settings/capability-matrix、GET /api/kline/daily、POST /api/kline/daily-batch、POST /api/kline/minute-batch、POST /api/backtest/strategy/run 与 GET /api/backtest/strategy/runs/{run_id}/evidence。具体参数/返回值必须从对应 api 文件与 OpenAPI 核对，不把本文路径清单当完整类型定义。

正式扫描缺少以下语义时必须增加薄适配，状态为“待实现”：按同一截止点冻结数据/证券池/参数；生成不可变输入引用；一次评估返回成功、无命中、失败三种不同结果；读前读后检查 generation；计算中数据换代则废弃本轮或有限重试，超过截止点终止。仅在新接口完成契约测试后，才允许称为一致扫描。

扩展启动上下文现有 RepositoryAccess 只公开 get_name_map；不能假定它已开放全行情、策略引擎或 app.state。新增接口只传必要的只读上下文和结果，使用已有服务组合；不建立第二份 provider、指标或前端缓存。

### 4.2 App / 中继

本地和 App 分别主动连接 wss://IP:8443/relay/v2/connect，使用角色 Bearer 令牌及二维码固定证书指纹；具体鉴权、角色绑定、TLS 和重连握手见云端设计。凭据不进入业务日志和导出证据。不存在 tenant、好友、Cookie 文件上传、云端消息历史 API。

业务命令与事件只消费 contracts/v2 的 schema；当前目录包含 40 个命令。已有事项操作、扫描控制、成交/对账、同步等继续使用集中命令注册；未决命令经 get_command_status 查询。文件流程消费 begin_upload、get_upload、finalize_upload、list_files、read_file、delete_file、cancel_transfer，register_image 只引用本地 fileId，cancel_import 取消识别；消息历史通过 get_messages 从本地读取。文件分块与流控采用 32 KiB 块、20 MiB 单文件上限、窗口 4；它们是 v2 上限，不能由某端自行放大。

内部接口职责按“读快照/验证候选/处理命令/投影事件/读文件块”划分。跨端任何字段扩展必须先更新 v2 契约和对应 fixtures，不能把内部 risk_budget 或训练清单字段直接添加到 App JSON。

## 5. 数据时间、行情与规则版本

### 5.1 四种时间与数据视图

每项影响决策的输入至少保留：事件/行情时间、公开时间（如适用）、首次获取时间、修订入库时间，以及来源标识、版本/内容 hash、单位与质量标记。这些是本地元数据要求，映射到跨端载荷时遵循 v2。

- 线上评估只用截至决策截止点本机已经获得且有效的输入；过去发生但今天才获取的公告不能倒灌到昨天的“当时系统判断”。
- 历史研究允许按公开时间重建可知视图，但必须注明供应商可得性假设；不等于真实运行重放。
- 新闻/公告只有日期无时刻时用保守可用边界；现有财务因子按公告后下一交易日起可用。不得把报告期末当公告时间。
- 每根 bar 明确是区间开始还是结束，收盘指标在 bar 完结后才可用；多周期连接采用已结束的高周期数据。
- 日线/分钟内部沿用内核明确口径；分钟 K 为北京墙钟 naive。进入跨端事件时按契约转换成明确时间，不能给 naive 值直接贴 UTC 标记。扫描、交易日、费用生效期均显式使用 Asia/Shanghai。

### 5.2 质量与版本

数据快照按 dataset、证券、日期、资产类型、周期、provider、规范化版本、源修订和 generation 索引。扫描清单固定策略代码 hash、参数 hash、信号/因子版本、规则版本、交易日历、证券池和持仓版本。缓存 key 覆盖上述会改变结果的输入；持久化后依次更新 generation、失效相关缓存、发布业务事件，禁止仅写文件而继续用旧内存。

质量至少区分可用、过期、缺失、冲突、未支持。OHLC 合法性、重复时间、负量、缺分钟、停牌与无数据、复权因子断点、单位比例、主数据缺失分开检查。异常进入隔离区，不覆盖最近有效版本；最近有效版本可展示但必须带旧时间，不能当新输入扫描。

原始成交价与复权指标价分别保存。涨跌停、最小报价单位与实际成交核验只用原始价格和对应日期规则；历史复权因子重算生成新数据版本，已发布事项证据仍引用旧版。财务与公司行为修订也追加版本。历史证券池应包括当时存在但后来退市/变更的证券；无历史池时明确存在幸存者偏差。

交易规则快照由证券主数据确认交易所、板块、品种、渠道，记录生效日期、官方来源、取得时间和字段冲突。范围沿用现有需求：完整核验先覆盖沪深主板、创业板股票及沪深场内 ETF 的已接入渠道；北交所默认排除，科创板和其他未接入渠道不冒充已支持。本文不重新发布法定费率或交易限制数字，实施时须核对官方当日规则，规则快照缺字段即降级，禁止按代码前缀、名称或最新版本猜历史。

## 6. 扫描、策略与风险预算

### 6.1 单轮执行

1. 检查交易日历、扫描时段、暂停状态、恢复门禁、数据就绪与上一轮租约。沿用需求的 5 分钟节奏和时段；进程停机错过的扫描不排队补发。
2. 冻结输入，记录计划/实际时间与策略清单。所谓 25 策略是配置验收目标，不是新装内核保证内置 25 个；缺少策略必须显示缺项，不虚构成功数。
3. 策略有界并行，结果分成功有候选、成功零候选、失败。核心输入缺失整轮失败；个别失败整轮 partial，成功候选按原阈值继续，不降低共振门槛凑数。
4. 按支持范围、数据质量、流动性、方向、冷却、共振、量化评分排序；AI 解释不参与排序。相似策略多次命中不是多个独立资金机会，同标的同方向合并。
5. 查询证据及可选 AI 补充；可信硬风险由固定规则否决买点，同时生成/合并风险事项。解释超时不阻塞确定性风险和台账；无外部核验则按既有规则标未核验，不能声称没有风险。
6. 发布事务内再次核对控制版本、持仓/预算/规则基线、冷却、单日额度与数据截止时间；变更影响风险则重新校验或抑制。业务变化和 outbox 同时提交，事务结束才发消息。

保留既有目标：扫描计算 P95≤5 秒、触发后 8 秒发布截止、在线传输目标预算 2 秒；这是验收目标，不是实测结果。AI/MCP 只用剩余预算；迟到结果保留审计，不能翻转已发卡片、延长有效期或作为新候选补发。性能达不到时降低并行计算工作量/明确失败，不能关闭数据或风控检查。

### 6.2 策略版本准入

本地策略登记流程：研究草稿 → 完成数据与因果检查 → 时间顺序样本外检查 → 影子观察 → 用户明确批准固定版本 → 正式启用；任何失败可停留原阶段，线上异常进入暂停。影子结果不得创建可操作买卖事项。

保存代码、因子、参数、预热长度、数据清单、成本/成交模型、所有研究尝试、随机种子、运行时依赖、OOS 结果、准入阈值及批准记录。代码或核心参数变更产生新版本，不能沿用旧批准。没有足够样本/OOS/历史版本时展示未验证，不编造稳定性分数。现有 /publish 只提供人工公开动作，新增本地准入注册还需把它与这些证据关联。

AI 生成的策略仅进研究区；AST 验证、资源限制和语义测试必须并存。执行使用无网络、只读数据副本、无业务写权限的工作进程；AST 白名单不能替代操作系统权限隔离。P0 可先禁用运行中 AI 改策略，保留已审查静态策略。

### 6.3 风险预算的工程定义

预算用于限制本地“建议新增风险”，不是真实账户可用资金。用户输入独立的计划资金上限/风险额度及有效期；未配置或过期时不输出可执行数量，只提供不含数量的观察信息。未录入现金/完整账户信息时不得显示“可以买入多少由账户保证”。

本地配置包含单标的、单策略、相关策略组/行业、总名义敞口、单日新增预算和最大并存事项数。阈值由用户策略档案明确设置并版本化，本文不预设适用于所有人的投资比例。风险数值只使用可追溯价格、用户确认的持仓/成本和确定性止损距离；无止损距离时损失预算不可计算，不用 AI 目标价补齐。

这些预算是新增本地领域配置，首期由本地管理入口校验并保存；不假定现有 v2 set_settings 已包含相应字段。若需要在 App 修改或显示细粒度预算，先扩展共享 schema/错误与 fixtures 后再接入，不能以自由 JSON 绕过契约。没有这部分配置时保持“无带量建议”的明确降级。

若输入完整，允许的候选数量取以下各上限的最小值再按当日适用委托单位处理：剩余名义预算÷参考价、剩余风险预算÷单位风险、单标的/策略/相关组剩余容量。费用和滑点压力应计入预算消耗。数量为 0 则不生成带量建议；价格/单位风险不为正、NaN、分母未知时拒绝数量计算。

活动事项对建议预算做本地预留，发布、释放与事项变更同事务。预算只在确认忽略/到期且没有执行申报或未决提交时释放；已声明执行但缺成交数据的预留进入待核对，不直接释放。记录成交后转已记录敞口；离线未知命令不重复预留。多策略同一标的共享容量，App 上多个按钮并发不能绕过总量限制。

对持仓卖出只核验已记录可卖数量，未知则不能声称可卖；不阻止用户记录已发生的成交。数据冲突、持仓待对账、预算错误、系统恢复期间，阻止对应新增风险；风险事实提醒仍可保留但不编造卖出数量。回测 PositionSizingPolicy 的异常等权回退不得复用于此门禁。

## 7. AI 事实包与可解释性

事实包包含来源地址/本地证据引用、正文或必要摘要、发布日期、获取时间、适用证券和规则、质量/冲突、内容 hash。AI 输出只能引用包内来源，不接受模型凭空生成 URL 作为佐证。数字、单位、证券匹配和时间由程序校验；结论分事实、推断、未知，来源冲突不静默择优。

量化评分、止损位、目标位、持仓数量由确定性模块提供；不存在的值留空。硬风险分类来自固定规则匹配已核验事实，LLM 可帮助抽取待核验字段但不能单独作强制否决依据。已知拦截只能由新事实、确定性规则或明确的人工作业流程解除，不能通过提示词“忽略风险”绕开。

AI 工具只开放最小只读查询；外部内容按不可信输入处理。工具响应中的指令、上传要求和动态代码不执行。设置 token/时间/调用次数预算，熔断后停止本轮外部等待。正文可缓存，但缓存 key 含事实包、提示词、模型及参数版本，旧公告摘要不能当当前证据。

记录模型/提示词版本、请求摘要、工具结果、输出、拒绝/超时和校验结果。重放使用已记录结果，不能再次调用新模型修改历史。当前 LLM 可能知道历史之后的事实，历史“问模型该买什么”不能证明没有未来泄漏。

## 8. 人工成交台账与持仓对账

### 8.1 事实、投影与原委托

成交事实采用追加事件，至少在内部关联用户申报来源、实际成交时间、证券、买卖方向、正整数数量、十进制价格、费用（未知为 null）、价格口径、原委托信息（可选）、规则快照及警告、关联事项和纠错链。具体跨端字段以 v2 为准。SQLite 金额/比例用十进制文本或统一缩放整数；禁止先经过二进制 float 再转 Decimal。

实际成交与原委托分别核验：成交数量可以是部分成交数量；整手/零股规则检查原委托，不能将每笔实际成交强制凑成整手。平均成交价不能当逐笔价格校验最小报价单位。涨跌停成交事实可留痕，策略“可能买不进”过滤不是拒绝成交的依据。

实际成交时间必填，不能用录入时间补猜。独立补录不需要活动事项，过期事项的 act 被拒绝后可通过独立成交命令补录，不能把旧事项复活。结构错误/未支持范围按契约拒绝；支持范围内规则缺失、冲突或原委托未知时保留事实与警告，不能虚假显示完整核验通过。

### 8.2 应用与待对账

只有时间不早于该标的当前基线、无未决对账、数量/可用量足够且批次明确时才增减持仓。买入形成带可卖日期的批次；ETF 的交收属性必须来自当日规则或用户明确确认，UNKNOWN 不默认 T+0/T+1。日切只结转基线之后未到期批次一次。

历史倒序、数量不足、成本未知、重复来源疑似冲突、更正或公司行为资料不足时：成交留痕，标记待对账；不做一半扣减，不回填猜测盈亏。成本未知不必否认已知数量，但不能由此产生已实现盈亏；数量/可用量不确定时阻止依赖它的卖出候选。

同一券商流水标识/文件行重复可在已有可靠标识下去重；只有时间价格数量相同不能自动认定重复，因为可能是真实两笔成交。系统展示疑似重复供人核验。没有券商接入，不推断未成交委托、跨账户资金、完整手续费或融资状态。

对账通过用户确认的 as-of 快照建立新基线，校验当前持仓版本，记录前后数量、可用量、剩余冻结批次、成本来源、原因及已包含的成交清单。被标为已包含的成交不再次增减。旧于当前基线的快照只能进入历史证据，不能静默覆盖当前状态。

纠错追加新事实并引用被更正记录，原记录和首次命令回执不改写；统计使用有效链末端，受影响持仓进入对账。批次或成本不足则保持未知，不能将更正当作新的额外买卖。公司行为同样追加已核验调整事件，不用复权因子自动推断现金分红。

### 8.3 估值与复盘

P0 输出名称为“持仓市值曲线”，不是净值或收益率。每个估值点固定数量快照、价格来源/时间、规则、截止时刻和计算版本；缺价格或未决数量时总额未知，保留已定价小计和缺项。无持仓且无待对账才为 0，不用今天持仓倒算过去。

买卖、导入与人工调整作为数量变化标记；没有现金流和完整成本不得把市值增加称盈利。历史重算追加新点并关联原点，不能覆盖用户已见结果。回测绩效、模拟盘绩效、人工申报已实现盈亏与候选命中率分别展示，分母、样本期、未完成样本和费用覆盖必须明确。

## 9. 存储边界与事务

| 存储 | 目标内容 | 一致性和保留 |
|---|---|---|
| 本地业务 SQLite | 命令、首次回执、inbox/outbox、事项/提醒、成交事件、对账基线、持仓投影、业务消息历史、文件元数据、控制与恢复状态 | WAL、foreign_keys、synchronous=FULL、单写者；长期保留事实与幂等索引，清理不能让旧命令再次执行 |
| 内核行情目录 | 原始行情/复权/enriched 与现有仓库 | 复用内核；新快照清单固定版本；不直接由业务服务修改 Parquet |
| 本地证据目录 | 冻结输入、研究清单、规则/公告修订、必要 AI 证据 | 内容寻址、不可变；被历史记录引用的版本不可被普通缓存清理删掉 |
| 本地原图目录 | 上传完整原文件、必要缩略图 | 用户手动删除；不识别后自动删；逻辑引用不含任意绝对路径 |
| 本地临时目录 | 未完成上传、解码/处理临时文件 | 配额/可恢复会话/到期清理；临时清理不删除已提交原图 |
| App 本地 | 缓存、durable 队列、未确认业务命令及上传暂存 | 本地收妥与上传提交状态确认后按 App 策略清理；不能作为唯一备份 |
| 云端 | 活跃连接、有限内存队列和路由 | 不持久化消息、文件或业务状态；进程丢失由端点重试 |

内部逻辑实体：commands、command_results、transport_inbox、transport_outbox、business_events、tasks、reminders、scan_runs、candidate_audit、execution_events、position_baselines、position_lots、position_projection、reconciliations、valuation_points、data_manifests、strategy_versions、risk_reservations、ai_runs、files、upload_sessions、file_chunks、sync_state。实现时可合并表，但不能把必须同事务的事实拆成不同数据库写入。

普通写命令事务：检查命令身份/hash → 首次/重放判断 → 在同一事务核对当前 peer incarnation、业务 epoch、inbox 隔离状态与工作领取版本 → 状态与对象版本检查 → 业务事实及投影 → 首次业务 ack → 业务 outbox → 标记 inbox 处理结果 → 提交。唯一约束保护命令身份、提醒轮次与业务事件；正常世代内重试同命令返回首次 ack，同 ID 不同内容按 v2 冲突处理。失败事务无业务成功回执。worker 开始计算时做过校验不能替代提交事务中的世代检查。

事务提交后 sender 工作；发送超时只改变重试状态，不能回滚已提交成交。数据库只读、损坏或磁盘满时拒绝新写入，不发送收妥成功/业务成功；保留可读历史并发出可观测故障。持久化保证依赖本机磁盘语义，必须通过 kill/掉电模拟验证，不能只测试正常 shutdown。

备份默认沿用每日 03:00、保留 14 天的本地策略：使用 SQLite 在线备份 API，固定同一业务截止点及文件清单，再复制清单引用的不可变文件，最后写完成标记；中途失败不得宣称该份可恢复。清理与备份共享引用租约，不能边删文件边发布完整清单。无需 MySQL dump 或云端卷备份。仅每日备份的灾难恢复目标为最多损失最近 24 小时，必须在界面给出最新成功时间；当前磁盘与全部备份共同丢失无法恢复。可选异地备份须单独配置并加密，不自动上传原图。恢复用独立副本演练，核对数据库、文件和命令结果；不对现有运行数据演练覆盖恢复。

传输事件正文至少按云端设计保留 30 天；未收妥/未业务确认记录不得按期清理。扫描与拒绝审计默认 90 天；被事项、成交或研究结果引用的证据按引用期保留。行情分钟缓存可按既有 90 天策略清理，但已经作为不可变研究证据引用的输入不能随缓存一起删除，若用户明确删除则相关重放显示资料缺失。

## 10. WS 持久收妥、业务回执与恢复

### 10.1 正常投递

每条传输以 deliveryId 与 payloadHash 定位；没有累计消息游标。对端先持久化 inbox，再发送逐条 receipt。云端接收/转发只说明网络状态，不能当持久收妥。重复相同传输返回相同语义 receipt；相同身份不同内容拒绝并保留冲突证据。

本地 receipt 只证明命令被 durable inbox 收下，不代表命令业务执行。处理器随后执行事务并生成独立业务 ack；App 必须等业务 ack 才将命令视为接受或冲突。发送端即使已获 receipt，也不得删除仍未获业务 ack 的命令 outbox；按 v2 时限先发只读 get_command_status 查询首次结果，不把等待超时当失败。普通同世代的传输重投仍使用原不可变内容与幂等身份；跨世代或执行结果未知时禁止自动重发业务命令。

本地业务 ack 自身也经 durable outbox 传递；App 落库后回 receipt。业务 ack 丢失时，查询或允许的原命令重投都不能再记一笔成交。事件已收妥但界面没展示、消息已送达但通知权限关闭都不是业务失败，投递与展示指标分别统计。

### 10.2 未决命令的只读查询

get_command_status 的目标由 originalEpoch、targetClientMsgId、targetRequestHash 指定；查询自身有独立 clientMsgId 和当前 serverEpoch。每次重新查询使用新的查询 ID，目标三元组不变，避免重用查询 ID 只取回上一次 processing/not_found 回执。处理器在同一短事务的一致快照里同时检查该认证配对范围内的命令账本和 durable inbox；需要保存查询回执/原 ack 重投时走现有单写者事务，不先持长只读事务再争抢升级写锁。查询对目标业务只读，永远不执行、恢复或解隔离目标命令。

| state | 判定与 ackEventId | 调用方行为 |
|---|---|---|
| found | 目标 epoch/ID/hash 匹配且首次业务 ack 已提交；ackEventId 为原 ack 的 eventId | 本地将原 ack 加入持久重投，保持原业务内容与 eventId；App 核对原请求，跨 epoch 的旧 ack 仅作恢复证据，不覆盖新纪元状态 |
| processing | 原命令存在 inbox/处理中任务，hash 匹配，未隔离且尚无最终 ack；ackEventId=null | 等待并重新查询，不能新建替代业务命令 |
| quarantined | 匹配的原命令已因世代变化/恢复隔离且未提交结果；ackEventId=null | 保持隔离，走对账流程，查询不能唤醒执行 |
| not_found | 在当前可用账本及 inbox 都无目标记录；ackEventId=null | 仅表示未知，尤其恢复后不能证明从未执行；不得自动重发 |
| hash_mismatch | epoch/ID 已存在但 hash 不匹配；ackEventId=null | 禁止关联或覆盖原记录，展示冲突并人工核对 |

已有提交结果优先返回 found；不能仅因它的旧投递 inbox 后来被标为归档就误报 quarantined。found 的查询结果与原 ack 重投入队应同事务；网络重投在事务后执行。状态查询也校验配对身份，不能跨用户/配对泄露历史结果。业务 ack 引用损坏或丢失不能伪造 found，须标运维故障并保持恢复门禁。

### 10.3 incarnation 与快照恢复

端点 incarnation 持久保存，普通进程重启保持；安装重建、数据库恢复到旧快照必须改变。它是传输端点世代，不应与业务恢复纪元、事项操作版本、行情 generation 混用。

本地观察到新 app incarnation 后，在同一个 SQLite 写事务内更新持久 peer 身份/世代版本、隔离旧 incarnation 尚未提交业务结果的 inbox（含已被 worker 领取的记录），并将旧定向 outbox 转同步等待。该事务与业务 worker 的提交共享单写者串行边界：业务先提交则保留事实，状态查询得到 found；peer 变更先提交则旧 worker 的世代/CAS 检查失败，不允许写业务副作用或成功 ack。仅关闭旧 WS 或仅冻结 App outbox 都不足以阻止本地旧排队命令执行。进程重启重新加载持久 peer/fence 状态，不能重新激活旧领取记录。

恢复步骤必须在监听与业务任务启动前执行：

1. 取得单写者锁，以在线一致备份恢复数据库及清单，检查完整性、schema 与文件 hash；记录备份截止时间。
2. 原子写入新 incarnation，按 v2 更新业务恢复纪元并开启恢复写入门禁；恢复的 outbox、提醒、上传会话与旧命令进入隔离状态，不能自动重发/执行。
3. 仅开放认证、状态查询、同步和恢复所需命令。对端 incarnation 变化时，即使本机未恢复，也停止旧队列重放并先同步；不能把未知旧命令重新包装成新命令执行。
4. 用本地已恢复事实、App 未决命令/已收业务证据和用户确认快照对账。云端没有历史可回补；App 缓存只是证据，不是自动覆盖本地权威的依据。
5. 逐条以 get_command_status 查询旧命令：found 重投原结果，processing 等待，quarantined 保持隔离，not_found 保持未知，hash_mismatch 禁止关联；已证实副作用但结果资料缺失进入人工核对。任何跨纪元或未知结果的重提必须经用户核对后形成新命令，不能仅因为超时或 not_found 自动重做。
6. 验证所有差异、文件完整性和待核对成交，按 v2 恢复确认流程解除门禁；不重放旧提醒，不补发过期信号。被中断的扫描标失败，合法时段重新开新轮次。

快照同步是本地权威业务视图，不能代替未决命令回执。发现本地与 App 都丢失某段事实时，明确缺口并靠用户补充，不宣称无损恢复。备份恢复时钟/标识回退必须作为故障注入用例。

### 10.4 WS 提醒调度补充（2026-11-15）

对已有 Task 的 nextReminderAt 调度，事务写入事项版本、提醒轮次、当前窗口、task_actions 和现有中继 outbox。critical 首轮之后按既定 T+5 分钟、后续 3 分钟规则继续，warn 最多两轮，info 无重复轮次；本模块不创建扫描事项或补造行情。展示窗口不超过 60 秒或事项有效期，晚于窗口的轮次不补发；系统恢复门禁关闭调度，暂停期间不产生提醒，snooze 到期按已确认时间推进。

普通重启不重复推进；过期、已处理、暂停或已被新窗口替代的提醒 frame 保留为不可变证据并停止重投。换手机只隔离旧定向投递和旧活动窗口，保留未来合法轮次；恢复旧备份属于不同情形，必须解除旧纪元调度并完成恢复核对。扫描、规则和 AI 仍未实现时，不能因为提醒调度可用就将整体 readiness 报为成功。

## 11. 文件原图、OCR 与删除

上传顺序：App 固定文件内容及 hash → begin_upload → 分块发送/查询缺块 → 本地校验长度、类型、块与整文件 hash → 原图原子入档 → 元数据提交 → finalize_upload 业务回执 → register_image 引用 fileId。全程通过 v2 中继，不存在云端上传 URL。

每块只有在数据已可靠写入且收妥记录可恢复后才回 receipt；网络断开按 get_upload 返回状态续传，重复块不能重复计数。同索引不同内容拒绝；不能仅凭 App “已上传完成”进入识别。文件名只作展示，服务器生成路径，校验解码尺寸、允许类型、大小上限、路径穿越与符号链接。

每个 uploadId/fileId 归同一个串行文件 actor 管理，别名映射不能使同一文件落到两个独立队列；块写入、finalize、取消、过期、租约取得与删除状态变更均经过它，并以数据库状态/version CAS 防重入。多进程部署仍须保留单文件写所有权，不能只靠进程内锁。长文件 I/O 不持数据库写事务：先保存操作意图/领取版本，在 actor 内做 I/O，再事务检查版本与状态提交；取消或过期已胜出则迟到完成不能变回 available。并发重复块不能各自读到“不存在”后重复写入或增加计数。

文件和 SQLite 不能同一个物理事务：先写临时块并同步，完成后同卷原子重命名，最后提交可见元数据；中途崩溃只留下不可见孤儿或可恢复会话，启动扫描按清单修复/隔离，绝不显示“成功但缺原图”。本地收妥成功后才允许 App 清除其上传队列副本。

OCR 只生成草稿与持仓差异预览，识别完成不直接改持仓；确认时校验预览版本、内容 hash 与持仓版本。来源图、原始识别、人工改动和最终确认关联。未获得第三方视觉授权时只能本地保存/人工录入，不上传外部 API。授权说明包含本地留原图、云端仅转发和外部服务的数据政策；不承诺删除第三方持有的副本。

register_image 的 available 检查、识别任务建立和持久 lease 获取在同一事务；识别 deadline 默认 120 秒并落库，正常完成、失败、超时或 cancel_import(importId) 都通过 actor/CAS 终止任务并释放 lease。cancel_import 返回 cancelled 或 already_terminal；取消回执只在本地读取者已退出/文件句柄已释放后生成，第三方请求可能继续但迟到结果不得复活 cancelled 导入、发布预览或更改持仓。崩溃恢复先结束过期任务与租约，再开放删除。

read_file 创建下载任务时同样事务检查 available 并取 lease；所有块收到匹配 receipt 后释放，cancel_transfer(transferId,kind=download) 或 24 小时到期也持久终止并释放，断线不续租。cancel_transfer(kind=upload) 只取消未完成上传并清理临时块；已完成则返回 already_complete，不删除已归档原图。取消成功返回 cancelled，持久取消墓碑阻止迟到块重建任务；下载取消停止后续发送，已交付缓存由 App 管理。下载完成 receipt、取消与到期必须串行/CAS 竞争，租约只释放一次，不能使客户端崩溃永久阻塞 delete_file。

手动删除先检查授权、baseVersion 和持久处理租约；识别/下载仍持有租约时按 v2 返回 FILE_BUSY，不改变文件可用状态，用户等待或取消相应任务并释放租约后以新命令重试。无租约时在同一临界区进入 deleting、禁止新读取与识别，再删除原图及派生副本，最后提交 deleted 与业务结果。删除失败保留可见待处理状态，不误报成功。保留必要的脱敏 fileId/hash/删除审计与结构化确认记录，不能反向恢复原图。已发往外部视觉服务的内容不能通过本地删图撤回。

备份可能保有先前原图：设置必须说明备份保留周期和清理方式；恢复后应用最新可获得的删除 tombstone。若只剩旧备份而无法确定备份后的删除记录，恢复图片先隔离、对账确认后才可见，不能声称自动知道用户后来删过什么。本地删除不删除用户相册原图。磁盘不足时拒绝新上传并保留现有原图，不未经用户请求自动淘汰档案。

## 12. 状态与故障矩阵

| 场景 | 业务状态/允许行为 | 恢复动作与验收点 |
|---|---|---|
| 云重启/网络抖动/对端离线 | 本地台账照常；队列持久待发，App 显示未同步 | 重连逐条重试；没有云历史依赖；不会重复副作用 |
| receipt 丢失 | 发送端保留传输，业务不因超时改写 | 同身份重投，inbox 去重 |
| receipt 已到、业务 ack 丢失 | 命令仍待确认，不展示成功 | get_command_status 同查账本/inbox；found 重投原 ack，其余保持真实等待/隔离/未知 |
| 已提交业务后崩溃 | 成交/事项/首次 ack/outbox 一起存在 | 重启恢复发送，不重新执行命令 |
| 暂停与扫描同时完成 | 暂停控制版本优先 | 发布事务重新校验，暂停回执后不新增该轮事项 |
| 行情延迟/缺分钟/来源冲突 | 阻止依赖输入的候选，展示最后有效值与旧时间 | 数据恢复后新轮次，不补发旧候选 |
| 部分策略失败 | partial，保持门槛 | 成功输入覆盖足够才发布，失败不计零分 |
| AI 超时/格式错误/来源缺失 | 量化/确定性门禁可继续，解释未核验 | 不放宽风险；无来源硬风险抽取不能直接通过 |
| 持仓不足/历史补录/成本缺失 | 留事实，待对账；不错误扣减/算盈亏 | 显式快照对账，核验 resolved 清单，无二次应用 |
| 上传中断/磁盘满/hash 错 | 文件未提交，OCR 不开始 | 查询缺块或明确失败；已完成原图不受影响 |
| 删图时 OCR 仍运行 | FILE_BUSY，不改变可用状态 | 用户等待/取消识别释放租约后重试；deleting 状态拒绝新租约 |
| SQLite 写失败 | 不回成功，不接受新写；只读历史可用 | 完整性检查与可恢复重试，不跳过幂等表 |
| 本地恢复旧备份 | 新 incarnation、写入门禁、旧队列隔离 | 先同步对账；未知旧写命令不能自动执行 |
| App 重装/对端 incarnation 变化 | 持久 peer 更新和旧 inbox 隔离同事务，与 worker 提交串行 | peer 先提交阻止旧 worker；业务先提交保留原 ack；全量快照不代替回执 |
| OCR 超时/取消及迟到结果 | 120 秒 deadline、cancel_import 终止任务，释放租约 | 不复活导入、不生成新预览、不修改持仓 |
| 下载断线/取消/完成相互竞争 | 全部 receipt、cancel_transfer 或 24 小时到期终止并释放租约 | 单文件 actor/CAS 只释放一次，迟到块不重建取消任务 |
| 系统时钟回拨/跨日/休眠恢复 | 时序异常门禁，旧扫描终止 | 单调时钟计耗时；交易时间按日历，重新取截止点 |

## 13. 回测与量化验收

复用现有 backtest/evidence.py 的输入指纹、截断/扰动和成交时序审计，不声称有限采样等于全策略无泄漏。新增准入报告必须展示数据历史版本覆盖率、检查分支、预热敏感性、样本外与成本压力结果。

- 时间：收盘信号不提前成交；公告盘后/晚到/修订不提前可见；高周期 bar 未结束不流入低周期；历史财务与主数据变更不改写旧证据。
- 样本外：按实际交易日构建新模式窗口；旧 timedelta 自然日配置标注原语义并版本化。训练拟合不含未来标签；清除跨分界标签；测试重叠不连乘成单账户收益。
- 成本：显式版本化费用、最低收费和滑点；当前默认费用不能当法定费率。日线/分钟降级结果分别标记，窗口不全不能称分钟精确。
- 退出：engine.py 独立候选尾部 force 平仓不得当可成交收益；新报告应留未平仓数量与末日估值，只有满足成交约束的部分算模拟已实现。
- 仓位：单标的/总敞口/现金等回测约束保留；正式建议预算再按本地台账约束。回测策略失败、样本不足、风险预算计算异常不得变成“零风险”。

### 恢复非成交操作的补充规则（2026-11-15）

## 15. 两轮自查结论及未验证项

第一轮核对源码与现有需求：保留已实现的因果审计与仓位契约，指出财务修订、自然日窗口、候选尾部强平、模拟盘与人工账户的区别；不虚构公共风控接口。第二轮按崩溃、断连、恢复、原图删除和并发预算复查：补齐 receipt/业务 ack 分离、命令不得过早删除、incarnation 改变后的未知命令隔离、文件提交与 SQLite 的非原子边界、原图备份删除语义。
