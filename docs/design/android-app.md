# Android App 设计 · v2 轻中继架构

状态：可实施设计，2026-11-15。本文与 [13 屏 HTML 原型](../app-ui/index.html) 配套；HTML 为样例交互，不是 Android 实现或功能验收。接口字段、错误枚举及帧上限以当前 [三端契约](../11-三端接口契约.md) 和 `contracts/v2` 为准。旧文档中的 IM 租户、好友、Cookie、云端历史/文件和自动清理原图语义不再适用。

## 1. 产品边界与设计取舍

App 用于查看事项、人工判断、记录实际成交、维护持仓和与本地助手对话。用户在券商完成交易后才回填；所有买入、卖出、清仓入口都必须出现“成交记录 / 回填”，确认动作明确“非下单”。不连接券商、不使用未知现金估算账户资产、不把 AI 答复当作交易指令。

沿用现有深色界面、A 股红涨绿跌、五个主导航和 13 屏顺序。选择渐进优化：提高字号与可触达性、稳定状态语义、补齐连接与恢复流程。重新制作无关首页会改变熟悉的路径；只换颜色则不能修复离线成功错觉与过小控件。新增配对、队列和文件管理作为设置/导入的辅助流程，避免扩张顶层导航。

三端职责：

| 端 | App 应当如何理解 |
|---|---|
| 本地服务 | 业务事实源；拥有业务 SQLite、命令幂等、可靠收发箱、原图文件库、扫描与 AI/提醒调度 |
| 云端 | 最简配对鉴权与双向 WebSocket 中继；没有持久数据库、历史消息、文件库或离线信箱 |
| App | Room 中的已确认投影、本机已同步历史、草稿、持久 outbox/inbox、文件暂存与提醒去重；提交意图，展示对端确认 |

“App 本机库是 UI 的读取源”与“本地服务是业务权威”并不冲突：网络事件先落库，UI 只观察已确认投影及待提交意图，不能让网络回调直接改界面为成功。Android 官方的离线优先指南支持这一读取模式与持久待写队列；本项目的业务冲突规则由本地服务决定。[Android 离线优先架构](https://developer.android.com/topic/architecture/data-layer/offline-first)

## 2. 信息架构与页面合同

五个主导航保持“事项 / 对话 / 选股 / 持仓 / 设置”。每个目的地同时显示图标与文字，选中态以底色、文字和语义状态共同表达；二级页保留所属 Tab。富文本页归属对话，导入归属持仓，暂停归属设置。五个目的地符合 Material 导航栏的数量范围。[Material Android Navigation Bar](https://github.com/material-components/material-components-android/blob/master/docs/components/BottomNavigation.md)

| 屏 | 首要问题 / 操作 | 必须保留的信息与异常 |
|---|---|---|
| 01 事项 | 现在需要处理什么 | 严重度、方向、状态、信号年龄、有效期；首次未同步、筛选无结果、0 候选、失败、过期分别呈现 |
| 02 详情 | 为什么提醒，之后怎么做 | 量化理由、事实来源、时间、未核验、提醒次数；底部“记录已成交 / 忽略 / 稍后”；终态只读 |
| 03 成交回填 | 记录我已完成的成交 | 逐笔价格、实际数量、时间、可选原委托；金额及持仓仅为预览；待确认/拒绝/待对账可定位 |
| 04 选股 | 哪些候选通过了哪些条件 | scanId、逐条策略、来源、数据时间、部分失败；本轮结果与下轮档案分开 |
| 05 持仓 | 当前已记录了什么 | 数量/可用、成本、现价、覆盖率、费用缺口；“已记录持仓口径”；待对账横幅及导入/手动入口 |
| 06 设置 | 连接和提醒是否可用 | 配对/凭证/对端状态、待发与隔离队列、提醒权限实际回读、模型只读诊断；不把开关当依赖健康 |
| 07 暂停 | 分析是否真的暂停 | 最后确认状态与待提交暂停/恢复分别展示；已有事项继续提醒；恢复不补扫历史 |
| 08 锁屏通知 | 哪条事项需要查看 | 脱敏内容、有效期、深链；权限/隐私条件下展示，不暴露不必要的持仓金额 |
| 09 前台强提醒 | 在前台及时看见严重风险 | 前台应用内提醒，确认后停止当前声响；回填、理由、稍后入口可触达 |
| 10 锁屏强提醒 | 系统是否允许这种呈现 | 仅作具备能力时的样式设计；无权时退回普通高优先级通知，不伪称全屏送达 |
| 11 对话 | 我发出的内容处理到哪一步 | 文本、快捷指令、来源；待发送/已接收待确认/答复独立；离线不生成虚假助手气泡 |
| 12 富内容 | 数字从哪里来 | 持仓市值曲线、资产分布、持仓表、采样时点、口径、缺价；回到对话保留输入 |
| 13 导入 | 原图存哪里，台账会改变什么 | 外部识别告知、可编辑结果、逐行差异、缺失默认保留、删除二次确认、原图保留及手动删除 |

原生 Android 使用单 Activity + Compose Material 3 + ViewModel/StateFlow 的单向数据流，Repository 向 UI 提供不可变状态。Navigation 保存 Tab 内滚动与草稿；系统返回先收键盘/关闭底部层，再回上级，不依赖屏序切换。HTML 侧栏、键盘左右键和上一/下一屏仅为评审工具，不进入产品。

## 3. 视觉系统与操作便利

### 3.1 色彩与排版

| Token | 原型值 | 用途 |
|---|---|---|
| 页面 / 卡片 | `#0D1118` / `#151A24` | 保留现有低眩光深色层级 |
| 正文 | `#F3F5F9` | 主要事实，卡片上理论对比度 15.97:1 |
| 次要 / 辅助文字 | `#AAB6C8` / `#99A7BC` | 数据时间、来源与说明；卡片上 8.49:1 / 7.14:1 |
| 主按钮 / 按钮字 | `#96BAFF` / `#0B172B` | 中性操作色，避免“记录”按钮被误认为买卖执行；9.19:1 |
| 上涨 / 下跌 | `#FF626E` / `#37D89A` | A 股习惯，同时保留 +/- 与方向文字 |
| 警告 / 信息 | `#F5B95F` / `#72A7FF` | 待核验、待处理 / 事实说明；不能仅依赖颜色 |
| 输入边界 | `#71829A` | 深输入底色上 4.59:1；焦点另加清晰描边 |

标题 24sp、标的名称 17–20sp、正文 15–16sp、字段标签 14sp、辅助文字最低 12sp；数字启用等宽数字特性。中文优先系统字体，Android 使用 sp，跟随系统字重/字体缩放；不依赖远程字体。HTML 已把原先 7–11px 文字提升至至少 12px，关键正文单独提升；这不等于已经通过 Android 大字体适配。

间距基于 4/8dp：页面水平 16dp、卡片内边距 16dp、段落间 16–24dp、字段间 20dp，卡片 18dp 圆角。数据密度通过分组和折叠规则说明控制，不缩小字体。价格、数量、实际成交时间先出现；原委托及规则来源是辅助信息，保留但不抢主操作。

普通文字目标至少 4.5:1，非文字交互标识至少 3:1；关键内容不得只用红绿区分。点击区域至少 48×48dp，标签与开关/复选框一起可点击；截图列表保留文本删除按钮，不能仅靠滑动。以上采用 Android 的无障碍指导。[Android 视觉与操作无障碍](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility)、[Compose 默认可访问行为](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)

### 3.2 单手操作与表单

- 记录、导入确认和消息输入固定在当前内容区底部，位于导航栏之上；底部同时说明“仅记录已成交”或“业务回执后生效”。详情先放主操作，忽略/稍后为次级。每屏主按钮不重复出现多个竞争动作。
- 长内容可滚动；底部留出操作区和系统手势区域。键盘出现时用 `imePadding`/窗口 Insets，导航与确认区不能覆盖最后一行或当前错误。系统栏、刘海、手势边距依据官方 Insets API 处理。[Compose Insets](https://developer.android.com/develop/ui/compose/system/insets)
- 数量用整数键盘，价格用小数键盘，日期与时间用独立选择器并显示上海时区。错误显示在对应字段下，焦点移到首个错误；输入和已填写内容保留。触发确认前再次校验，不仅依赖按钮禁用。
- 成交价采用十进制；实际成交数量为正整数，不套原委托 100 股倍数规则。规则缺失/冲突显示未核验/失败，不自动修正实际成交事实。平均成本与逐笔价格不是同一字段。
- TalkBack 读取“标的、方向、严重度、状态、剩余有效期、主动作”；装饰图标不朗读。按钮、分段选择、Tab 提供 role/stateDescription，切页聚焦标题，错误用可访问提示；倒计时不每秒播报。
- HTML 明确禁止把键盘输入中的左右键当屏导航；中文输入法组合阶段 Enter 不发送。正式 App 需支持键盘下一项、完成、返回和 TalkBack 焦点恢复。

## 4. 首次配对与连接状态

首次启动展示“连接我的本地工作台”。管理员离线生成 App 专属配置，用户扫码或导入配置后核对工作台标识及完整证书指纹。配置包含当前 v2 约定的地址、pin 与 43 字符的长期角色令牌 `appToken`；二维码携带长期凭据，应按凭据保管，不保存二维码截图到日志。手动导入配置是同等校验路径，不允许“忽略证书错误”。这里的配对表示导入可信配置并建立连接，云端没有配对兑换接口或一次性 token。

连接入口 `wss://IP:8443/relay/v2/connect`；握手使用 `Authorization: Bearer <App角色令牌>`。App 不能使用本地服务角色令牌冒充服务。角色令牌由管理员离线生成，不通过云端申请、兑换或刷新，也不展示虚构的到期倒计时。撤销和轮换由管理员修改云端只读配置并按部署流程使其生效，再向 App 分发新配置；被拒绝时引导重新导入管理员提供的配置。证书 pin 变化也需要核对可信新配置，不能自动信任网络返回的新 pin。

令牌由 Android Keystore 保护的密钥加密后放入 App 私有存储；Keystore 保存密钥，不是把任意 token 当 Keystore 密钥条目。禁止日志输出凭据、配对配置、完整二维码和原图内容。备份排除角色凭据；重新安装/恢复本机库时走新身份与恢复流程。Keystore 的不可导出密钥特性不意味着全部设备都具备相同硬件保护能力。[Android Keystore](https://developer.android.com/privacy-and-security/keystore)

| 状态 | 用户看到 | 允许动作 |
|---|---|---|
| 未配对 | 扫码/导入入口；没有当前服务数据 | 填写草稿与配对，不发送业务 |
| 手机离线 | 缓存、最后同步时间、待发数量 | 查看已同步内容、保存本地意图 |
| 云端在线/本地离线 | “本地服务离线，操作留在本机” | 保留待发；云端连接不代表事项已处理 |
| 两端在线/未追平 | “正在同步”；已确认缓存可读 | 等待身份/快照确认后恢复发送 |
| 可写在线 | 最近成功同步时间与剩余待处理数 | 按顺序发送与接收 |
| 凭证失效 | 令牌已撤销或配置不匹配；重新导入可信配置，本机数据保留 | 停止发送，不清空队列、不尝试不存在的云端凭据刷新 |
| 对端恢复 | “恢复待对账”；旧队列隔离 | 只读证据，逐项核对后开放写入 |

普通断线或重启不改变 incarnation。App 重新安装/恢复数据库、或本地服务恢复数据库造成对端 incarnation 变化时，先冻结旧队列、同步当前权威快照，再核对旧操作。切换工作台不可把旧意图直接重发给新配对身份。

## 5. 收发、业务回执与恢复

### 5.1 持久化与状态机

建议 Room 表职责：`confirmed_entities`/分页投影、`chat_messages`、`command_intents`、`transport_outbox`、`transport_inbox`、`receipt_outbox`、`file_transfers`、`notification_dedupe`、`sync_checkpoint`。字段与索引由 v2 schema 衍生，不在 UI 层创造另一套消息格式。

1. 点击提交时，在本机事务内写不可变意图、`clientMsgId`、预期对象版本和 outbox；提交落盘后显示“待发送”。落盘失败显示保存失败，不能退化为只存在内存的成功态。
2. 发送方保持 `deliveryId + payloadHash + 不可变 bytes`；重试保持原 ID/内容。中继写入 socket、云端返回路由状态、TCP/WS 成功均不代表对端持久收到。
3. 接收方核验身份、协议和完整性后，同事务持久 inbox/去重状态及待发端到端 receipt；提交完成后发送 receipt。重复投递再次确认，不重复副作用；同 ID 异 payloadHash 作为冲突。
4. 收到对端 receipt 后可释放传输重发资源，但保留命令意图，UI 显示“已送达，业务待确认”。对端业务 ack 必须独立持久接收；缺失时以原 `clientMsgId` 查询/重试，不能换 ID 再执行。
5. 只有本地服务业务 ack 及匹配投影可更新“已记录/已忽略/设置已生效”。失败/过期/版本冲突保留可处理记录；“成交已记录，持仓待对账”不是完整成功，持仓不能提前变化。
6. 双向都遵守同一规则：本地服务的回执、事项、聊天答复也在服务 outbox 保留到 App 持久 receipt。云端重启/断线不丢端点持久数据，重连只影响耗时。

UI 将待发意图与最后确认状态同时展示，例如“分析运行中 · 暂停请求待发送”。这比把开关先切为已暂停更重要。取消只对能证明从未发出的意图开放；已经发出但未确认的操作必须查询状态，不能把删除本机消息当作撤销远端动作。

### 5.2 重连与后台限制

连接重试采用契约指定退避与抖动；网络恢复/前台进入触发同步，发件箱按对象有序、有界窗口排空，文件传输不能饿死业务确认。用唯一 WorkManager 工作处理可延迟持久重试，不把 WorkManager、常驻 WS 或被系统杀进程后的唤醒当实时必达保证。后台数据新鲜度和提醒可用性单独显示。

恢复时先核对双方身份、取得完整快照和恢复状态，再恢复业务写入；旧队列按“已包含 / 待独立补录 / 放弃”分组，人工作出选择。本地已执行但 App 没拿到 ack 的旧意图，用只读 `get_command_status(originalEpoch,targetClientMsgId,targetRequestHash)` 查询；`found` 重投原 ack；`processing` 表示仍在处理，`quarantined` 表示已隔离，两者都保留待处理意图并等待查询/人工核对，不能当作失败后可新建执行；`not_found` 仅表示未知，不能自动重发或自动换纪元执行。旧意图不得以重发业务命令代替查询。本地服务的 incarnation 切换、旧 inbox 命令隔离和执行门禁在同一本地 SQLite 事务边界内建立 fence；业务提交须在事务内验证当前 fence，避免切换身份与旧命令并发执行。App 只有收到权威恢复状态和快照后才改变只读/可写状态，不能用一次 WS 重连推断 fence 已解除。旧事项已过期时不能直接重放 act/snooze；真实成交可经新的独立补录流程关联原事项，不能篡改原事项终态。

恢复非成交操作时，按本地返回的 `allowedDecisions` 提供 `archive_operation`：“已核对，保留恢复后的状态”。展示旧操作及当前状态，要求非空核对说明并引用全部关联证据；业务ack确认后才标记归档。不用旧ack更新当前设置，不自动重发，恢复完成后按需发起新操作。成交、持仓及原图独立复核门禁保持不变；不识别的新决定保持只读并提示更新，不能默认为included。

## 6. 原图、识别与手动删除

用户已确认：**原图保留在本地服务，可手动删除**。云端无文件存储；正常传输可以经过中继的有限内存窗口，不能把这说成云端上传成功或云端文件历史。

| 阶段 | App 展示与行为 |
|---|---|
| 选图 | 显示缩略图、文件大小、本地保留说明；外部识别单独告知；只选择需要的图片 |
| 准备传输 | App 私有暂存与持久传输任务；选择 URI 权限失效时可重选，不丢失草稿 |
| 上传 | `begin_upload` → 分块传输；`get_upload` 查询可续传进度。单块 32 KiB、上限 20 MiB、窗口 4，按 v2 完整性约束校验 |
| 文件完成 | `finalize_upload` 的业务结果确认后显示“原图已保存”；传输 receipt 不等于文件已 finalize |
| 识别 | 经同意后 `register_image(fileId)`；“识别中 / 失败可重试 / 部分需复核”独立于文件存在状态 |
| 差异确认 | 可编辑识别值；冻结批次、快照版本、逐行新增/修改/保留/删除；无有效结果不得一键清空 |
| 查看历史原图 | `list_files` 分页元数据，`read_file` 经同一可信传输取得内容；无云端 URL、不从任意外链取本地文件 |
| 删除 | 具体文件名、大小、关联批次、影响说明 → 二次确认 → `delete_file(fileId)` → 业务 ack 后显示已删除 |

离线删除显示“删除待发送”，原图仍显示保留；待确认期间按钮防重复，但原 ID 可重试。删除失败展示原因并保留原图入口；不存在/已删除的幂等结果按契约处理。删除不删除相册原图、不撤销既有台账，也不承诺第三方数据同步删除。识别/传输进行中的删除可能返回 `FILE_BUSY`，这是已持久保存的拒绝结果。用户可 `cancel_import(importId)` 或 `cancel_transfer(transferId,kind=upload|download)`，等待取消业务确认和 lease 释放后，以新的 `clientMsgId` 发起新删除。若删除中途断线而结果未知，则查询/重试原删除键，不能换键把未知结果当新请求。App 不擅自猜测取消或删除成功。

手动删除作用于当前本地服务文件，不保证旧备份已经擦除；默认备份保留 14 天，到期清理与实际备份策略单独核对。恢复旧备份时，缺少最新删除墓碑的原图必须隔离，不能因旧文件重新出现就开放读取或识别；先核对删除记录与恢复清单，再决定清理或恢复可用状态。App 对这些文件显示“恢复待核对”，不展示成正常保留原图。

原图长期保留需要在设置展示本地服务文件容量、筛选和逐项清理；空间不足提示停止新上传，不能悄悄删除旧证据。App 的下载缓存可独立清理，不等同于本地服务原图删除。HTML 目前表达单张文件元数据和二次确认，没有真实照片、文件上传/查看或批量管理。

## 7. 提醒与权限现实边界

本地服务负责生成提醒事件；App 验证 serverEpoch/当前事项/有效期/snooze/恢复模式后呈现，WS 与 MiPush 去重。送达 receipt、App 展示、系统通知展示和用户确认是不同证据。打开 App 后只补弹当前可处理事项，不把旧缓存转成最新提醒。

2026-11-15 当前接入选择为 **WS 提醒**，MiPush 暂未开通。App 增加本机“后台提醒”开关，默认关闭、绑定当前配对；用户在 App 可见时开启，并允许通知权限与连接状态通知渠道后，前台服务维持现有 WSS。常驻通知展示真实连接/同步状态并提供关闭入口；停止后台服务只释放它自己的连接租约，前台界面仍可使用连接。切换工作台清除旧配对的后台偏好；恢复门禁期间停止提醒。

前台服务声明 `specialUse` 及持续接收用户工作台提醒的用途，避免将长期连接伪装成有运行时限的 `dataSync`。仅在可见 Activity 中启动/恢复，不由开机广播或后台重试任务擅自启动。系统终止、强制停止或 Doze 断网仍可能中断接收；重新打开 App 后按已保存偏好恢复。分发到应用商店时另行完成该类型用途审核。[Android 前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types#special-use)、[Doze 限制](https://developer.android.com/training/monitoring-device-state/doze-standby)

重连同步中的 `currentReminder` 只作为核验线索，仍经实时 `get_task` 和持久提醒去重；通知点击再次查询当前事项，不重发通知或自动执行操作。后台提醒开关与服务端 `pushEnabled` 是不同设置：后者保留为未来厂商推送偏好，不控制 WS 事实事件。

手机与服务端轻微时差可能使已收到的当前提醒在手机上尚未到 `scheduledAt`。对身份、事项状态及当前提醒仍匹配的引用，App 可合并等待其起点，最多等待 60 秒；等待期间继续检查失效条件。到达起点后才执行原有实时查询，不能提前展示或延长 `displayUntil`。这只处理已收到的提醒，不根据 `nextReminderAt` 预排未来提醒。

Android 13+ 通知需要运行时许可；使用明确的通知渠道与返回后回读，不因点过设置按钮就显示开启。[Android 时间敏感通知](https://developer.android.com/develop/ui/views/notifications/time-sensitive)

Android 14+ 全屏 intent 默认授权受通话/闹钟用途限制，TickDesk 的股票提醒不能假定自动取得该能力。正式实现检查 `canUseFullScreenIntent()` 与渠道/锁屏权限，并采用普通高优先级通知或前台应用内提醒降级；不得通过假扮闹钟类别获取能力。原 08/10 屏保留为有条件样式，真机与分发渠道政策验收另行进行。[AOSP 全屏 intent 限制](https://source.android.com/docs/core/permissions/fsi-limits)

## 8. 验收与原型覆盖

| 场景 | 必须观察到的结果 |
|---|---|
| 本地服务离线、App 在线提交成交 | 本机 outbox 落盘，重启后保留；持仓不变；云端无离线消息落库 |
| 仅收到对端 receipt | 显示送达待确认，命令意图仍在；业务成功图标不出现 |
| 本地提交后 ack 丢失 | 原 clientMsgId 查询/重试只记录一次；返回首次结果 |
| App inbox 落盘后 receipt 丢失 | 服务重投，App 去重并重发 receipt，无重复历史/提醒 |
| 任一端普通重启 | incarnation 不变；未确认投递恢复；不全量隔离合法队列 |
| 本地恢复数据库 / 身份变化 | 旧队列隔离；写入和新提醒门禁关闭；完整快照与人工恢复流程 |
| 过期事项的离线操作 | 显示冲突，事项与持仓不伪成功；保留独立补录入口 |
| 25 股实际成交 | 可记录事实；原委托信息缺失标未核验；不会按 100 股倍数拒绝 |
| 空数量、负价、缺成交时间 | 就地错误与首错聚焦；没有待发条目；原输入不清空 |
| 文件已传完、识别失败 | 原图仍可查看/重试，台账不变 |
| 手动删原图且本地离线 | 待发送，原图仍标保留；恢复收到删除业务 ack 后才更新 |
| 320/360/390/412dp、200% 字体、横屏/键盘 | 主动作与错误可触达，内容不遮挡，Tab 文本可辨；金额可换行/横向查看 |
| TalkBack、键盘、减少动画 | 无图标重复朗读、焦点可预测、选择与错误可感知；不依赖颜色或滑动唯一入口 |

本轮原型已经补充：连接/配对场景、待发与对端接收待确认、模拟业务 ack、成交待对账、冲突、恢复隔离、列表空态/失败/过期、原图保留与删除二次确认。默认新操作停留在待发送；在设置显式选业务确认才展示确认演示。所有数据与队列仅在浏览器内存，刷新重置；不实现真实鉴权、WS、SQLite、AI、文件、通知、券商或后端。

两轮结构/导航/对比度/表单静态检查记录见 [迭代记录](../app-ui/iteration-notes.md)。当前环境的浏览器安全策略已拒绝本地原型预览，本轮没有用 HTTP/Playwright/CDP/原生浏览器等替代路径绕过。因此未完成视觉渲染、实际点击、布局溢出、软键盘、TalkBack 或 Android 真机验收；数值对比度只代表指定纯色 token，不能替代逐元素渲染检查。
