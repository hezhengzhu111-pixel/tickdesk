# Relay 开发记录

## 2026-11-15 · v2 云端中继

1. 独立的只读摘要文件每秒检查一次。候选先完整解析，在会话锁内提交并同步撤销所有失效的活动和待建连接。重叠轮换最多 600 秒。
2. HTTP/1.1 GET 认证成功后升级。hello 决定持久 incarnation，认证结果决定配对及角色。用同一会话锁串行化注册、替换、路由和清理。首个写入字节也在锁内检查双方 connectionId，阻塞的首次写入唤醒后重新检查。
3. 传输 Schema 离线编译。按 TD-C14N-1 规则解析并校验 hash 后原字节转发。在接收连接上限制队列，优先处理 WS 控制帧和传输控制消息，再按 8:1 调度业务和文件。末块的精确清单长度由接收端校验。
4. 监听层最多 512 条 TCP 连接。进程最多配置 100 个配对、200 个活动会话和 32 个其他待建或关闭中的 WS 会话。每 IP 握手突发 16 次、稳定 4 次/秒，全局突发 64 次、稳定 32 次/秒。每 WS 入口突发 128 帧、稳定 64 帧/秒，以及突发 2 MiB、稳定 1 MiB/秒的文本预算。
5. readiness 只在可服务且至少一个配对有两种有效角色凭据时通过。指标在独立 loopback 监听器提供，包含角色在线数、队列条数/字节数、心跳 RTT 与年龄、错误和关闭计数。启动与容器部署命令见 [README](../README.md)。

本地 Rust 验证通过 `cargo test --locked`（17 个测试）、`cargo fmt --check`、`cargo clippy --all-targets --locked -- -D warnings`。真实 TLS/WS 测试使用临时证书、临时凭据和系统分配端口。两个独立连接验证命令、原样 receipt、业务 ack、双向文件块及错误转发，并覆盖鉴权拒绝、子协议与 HTTP 方法、限流、配对隔离、角色冒充、receipt 反向字段、超限、失败重载和撤销。确定性测试覆盖阻塞首字节期间两种角色的连接替换、队列背压、组装超时和 Pong 期限。

11 个 v2 快照文件均与根契约逐字节比对并核对了本工程 manifest。根契约校验通过 127 个业务样例、11 个传输样例及 10,000 次参考故障演练。参考模型和双端点协议测试不能证明 App 与本地服务的持久化行为。

Linux 容器镜像构建成功。临时容器以 10001:10001 和只读根文件系统运行，经临时 CA 与 IP SAN 校验后报告 healthy。空 `[pairs]` 原子重载使 HTTPS readiness 从 200 变为 503，liveness 保持 200。容器内 loopback 指标和 `--check-config` 均可用，SIGTERM 退出码为 0。

待真实 App、本地服务和 relay 三端联调。待验证 Android 后台重连、端点持久化与磁盘故障、端点 SPKI pin 轮换、实际网络以及 24 小时文件与消息并发 soak。端点指标与 error 的协议商议见 [契约待确认项](contract-issues.md)。
