# v2 联调问题

以下记录不改变 App 中的契约快照或共享协议。

| 事项 | 影响 | 建议 |
|---|---|---|
| 私有 CA 的信任配置 | v2 配对配置只携带 SPKI pin，App 使用 Android 信任链 + IP SAN + pin。自签名或私有 CA 没有 `PairingConfig` 中的信任链字段时，默认 App 无法验证该链。测试仅在测试代码中添加测试证书。 | 部署说明明确 Android 可验证的证书链方案。如果要求独立私有 CA，三端先约定可验证的信任根分发方式。 |
| WebSocket 心跳 | OkHttp 的公开 WebSocket 接口支持 15 秒 ping 和 pong 超时，尚未实现规范要求的 8 字节随机 nonce、最近三次匹配和精确 45 秒窗口。 | 与中继进行心跳互通和掉线测试，再完成精确的端点心跳验收。 |
| 历史富内容附件 | `Reply.attachments` 保存引用 ID、symbol 或 scanId。快照之外的历史持仓或估值引用缺少通用的不可变对象读取入口。App 保留引用和来源，当前台账明细单独呈现。 | 明确各 attachment 类型的历史解析入口和缺失回退。 |
| 原图存储用量 | `list_files` 提供分页文件大小和状态。现有状态结果缺少原图库总用量、保留区占用及可用空间，设置页无法展示权威容量。 | 在后续契约中协商由本地服务返回原图库用量与可用空间，按实际范围标注。 |
| 最新原型的行情和估值字段 | 候选页可读取涨跌幅、量比和总市值。流通市值、换手率和持仓板块、今日盈亏缺少对应字段。历史市值采样提供市值、时间、完整性与版本，区间市值变化无法作为历史累计盈亏展示。 | 如保留这些展示项，由工作台提供带采样时点和口径的字段。历史持仓分布需要能关联到答复时点的不可变持仓版本。 |
| 首笔成交的规则核验 | 成交台账允许记录真实已发生成交。App 可复用证券、交易日和渠道匹配的已同步规则快照，当前服务写入成交时规则快照可能为空。 | 提供版本化规则查询或在成交回执中带上实际核验快照，明确交易日、标的和渠道的适用范围。 |
| 选股行情刷新 | `get_candidates` 读取已生成扫描结果，App 的同步按钮据此刷新结果。现有命令无法单独刷新当前批次的行情并返回新行情版本。 | 如需独立行情刷新，定义结果的批次关系、行情版本、采样时间及部分数据的状态。 |
| 报告追问上下文 | `chat` 仅接收文本，App 将报告标识与有限的未核验答复摘录附在追问文本内。工作台按单次请求提供冻结证据。 | 若需恢复完整报告上下文，增加可核验的原报告引用，并定义权限及关联证据。 |
