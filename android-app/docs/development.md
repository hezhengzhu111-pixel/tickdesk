# Android 开发记录

## 2026-11-15 · 实施与验收顺序

现有 Gradle、Compose 五标签页、深色主题和纯 Kotlin core 继续使用。开工前基线构建通过。

1. core 从应用随附的 v2 schema 验证 wire DTO，从原始 JSON 严格解析并生成 TD-C14N-1 摘要。用共享业务、传输及摘要向量验收。
2. Room 持久化队列、身份和投影，写入意图与 outbox 同事务落盘。经过 fixture 驱动的 Repository 测试后连接可信配对、Keystore 和 WebSocket。
3. 核对重复投递、丢失业务回执、快照乱序与身份变化。快照验证后原子发布，服务端恢复状态约束重放。
4. 五标签及二级页面观察 Repository，逐步接入事项、成交、选股、持仓、设置和对话。UI 保留确认投影和待提交状态。
5. 原图与识别流程以传输和业务结果分别推进。加入通知、前后台连接与设备检查。

验收使用 `gradlew.bat :core:test :mobile:assembleDebug :mobile:lintDebug`。Room 事务与重启另在 Android 运行时进行验证。实际设备与联调范围在交付段落记录。

## 2026-11-15 · UI 优先交付

- 延用五个主 Tab 和深色设计。增加事项详情与成交表单、选股结果和档案、持仓更正与估值、设置与恢复检查、暂停、对话及来源、原图元数据与识别确认。聊天输入位于内容区底部，软键盘出现时使用 IME Insets。日期和时间可直接输入或用系统选择器。

- 配对支持扫码与 JSON 导入。确认界面展示工作台、地址与完整 SPKI pin。凭据保存于 Android Keystore 加密的私有文件。连接使用严格 TLS、WS 子协议和身份核对。连接身份变化会隔离旧操作。
- 原图选择验证 JPEG/PNG 格式、大小及像素上限，预览使用降采样。识别同意、撤销、差异确认、取消导入和删除入口已接入业务意图。分块上传、下载、传输续期和保留策略仍待接入。
- 前台严重提醒及普通 Android 通知入口使用核验后的事项与持久去重。通知权限从系统回读，打开通知可定位事项。尚未进行实发通知、锁屏呈现和 MiPush 验收。

## 2026-11-15 · 原图、恢复对账与提醒

- 选择 JPEG 或 PNG 后可核对尺寸、大小和缩略图。保存时验证所选内容，传输任务及分块先存入 Room。上传断线后回查已收块，沿用原分块标识。收到文件完成的业务结果后显示已保存，识别需单独取得同意。
- 原图列表支持翻页。下载按块校验并比对完整 SHA-256 后才展示。取消和删除均等待业务回执。删除要求核对文件和版本，作用于本地服务的原图。工作台身份发生变化时隔离旧传输。
- 设置增加恢复对账，收集保存的旧命令、业务回执和旧快照，按服务返回的允许决定处理非成交差异。封存和确认发出前核对冻结证据，新到达的原回执会要求重新核对。服务确认会触发正常模式全量同步，手机的隔离队列仍需人工确认。
- WebSocket 与推送引用走同一事项核验流程。核对工作台、服务纪元、事项版本、是否仍可处理、稍后时间和提醒有效期。夜间按上海时间和已确认配置安静呈现。设备点击通知时再核对持久化记录及服务身份。推送回调适配器等待 MiPush SDK 接入。

## 2026-11-15 · 逐屏验收后的交互调整
